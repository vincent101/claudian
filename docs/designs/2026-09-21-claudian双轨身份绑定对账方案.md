# 背景与问题

Claudian 3.1.1 同时用 host runtime 与 transcript observer 描述同一逻辑轮，当前依赖租约、到达顺序和 `lineOffset` 启发式对齐；该结构已三次补丁化修正，仍留下 `notificationResultPending` 在 notification result 永不到达时吞掉 host result、令用户轮挂起的未闭环路径。

本记录给出待事件触发后实施的目标方案。当前只设计，不修改实现。由于 frontmatter 的项目设计记录状态枚举仅有 `draft | confirmed | superseded`，本记录以 `status: draft` 保持格式合法，并用 `lifecycle: parked` 与 `trigger` 明确“挂起待触发”。

## 解层次检查

难点不应继续停留在“给 boolean 增加更多清理分支”的实现层。根因在更上一层：系统没有一个同时认识 feature turn、SDK user UUID、transcript row 与 observer mirror 的身份所有者。只要 host 与 observer 各自建轮，任何顺序修补都会继续把“同一事实的两个观测”误当成“两件事”。因此目标是先建立 provider-local 身份绑定与对账边界，再让租约和通知消费对账结论；不重写 `ProjectionWriteCoordinator`，也不把 Claude 私有 transcript 结构上提到 provider-neutral core。

# 方案设计

## 1. 方案比较与裁决

| 方案 | 做法 | 优点 | 缺点 | 结论 |
|---|---|---|---|---|
| A. 继续强化顺序启发式 | boolean 改计数器，增加窗口/offset 清理 | 改动最小 | result 缺身份、双轨双计仍在；继续积累例外 | 否决 |
| B. runtime 直接吸收 observer | 把 mapper/observer 状态塞进 `ClaudeChatRuntime` | 单对象看似易调度 | runtime 同时承担 SDK、文件尾读、对账、租约；更难测试与演进 | 不推荐 |
| **C. provider-local 独立对账器** | transcript UUID 为 canonical；host/observer 都上报事实，由 coordinator 绑定、裁决 mirror、管理 notification claim | 身份、归属、诊断单一；保留现有租约与投影边界；可三批迁移 | 增加一个明确组件与事件契约 | **采用** |

推荐新增：

`/Users/vincentwang/Documents/NoteVault/tools/claudian/src/providers/claude/runtime/ClaudeTurnReconciliationCoordinator.ts`

它只负责：

- 身份绑定；
- 两轨观测去重与冲突裁决；
- notification result claim 状态机；
- 对账诊断与 timeout 后请求 runtime 重建。

它不负责：

- 读 transcript 文件；
- 转换 `StreamChunk`；
- 持有 MessageChannel/feature/DOM 租约；
- 渲染、保存或通知 UI；
- provider-neutral capability 判断。

依赖方向固定：

```text
ClaudeMessageChannel / ClaudeChatRuntime ─┐
                                         ├─> ClaudeTurnReconciliationCoordinator
Mapper / Observer ───────────────────────┘                 │
                                                           ├─ verdict -> runtime settlement
                                                           └─ verdict -> observer promotion

ProjectionWriteCoordinator <─ AutoTurnProjectionController（保持原边界）
```

## 2. 轮身份模型

### 2.1 canonical ID

采用 **transcript user row 的 `uuid`** 作为 `canonicalTurnId`。

理由：

1. 它同时出现在 host 构造的 SDK user message 与最终 transcript，天然可跨两轨验证。
2. external/peer/channel/coordinator/task-notification 没有 feature `turnId`，但都有 transcript UUID；反向采用 feature `turnId` 会迫使 observer 再造 host 身份。
3. rewind/fork 已使用 provider-native user/assistant UUID；统一 vocabulary 后不需再引入第三种持久锚点。
4. UUID 是身份，不承担时间顺序；因果序继续使用 transcript byte offset。

作用域仍带 session generation，防止 session switch/restart 的迟到事件误命中：

```ts
interface ClaudeTurnIdentity {
  canonicalTurnId: string;      // transcript user UUID
  sessionGeneration: number;    // runtime-local epoch，非持久 ID
  hostTurnIds: ReadonlySet<string>; // feature turn aliases，至少 0 个
  transcriptUserId: string;
  origin: 'host' | 'external' | 'notification';
}
```

对外 `AutoTurn*Event.turnId` 暂保留 string 兼容，但其语义冻结为 `canonicalTurnId`；host feature lease 仍使用原 feature `turnId`。二者只经 coordinator 映射，不比较字符串、不互相冒充。

### 2.2 映射建立时机

分三步，不把“生成”误当“已落盘”：

1. **reserved**：`ClaudeUserMessageFactory` 生成 UUID 后，runtime 登记 `hostTurnId -> candidateTranscriptUuid`。
2. **dispatched**：MessageChannel 真正 dequeue 时确认该 queue item 的 canonical UUID，并绑定所有合并进入该 item 的 host aliases。
3. **observed**：observer 读到同 UUID 的 user row 后，补 `lineOffset` 并把 binding 标为 transcript-confirmed。

只有 `dispatched` 才可用于 runtime result 归属；只有 `observed` 才可用于 transcript 因果比较与 rewind/fork 目标能力。

### 2.3 先修正 MessageChannel 身份保存

`/Users/vincentwang/Documents/NoteVault/tools/claudian/src/providers/claude/runtime/ClaudeMessageChannel.ts` 必须满足：

- text queue item 保存完整 canonical `SDKUserMessage`，merge 只改 content，不重建并丢 UUID；
- attachment replace 只替换 payload，保留 queue item 的 canonical UUID；
- queue item 记录 `hostTurnIds[]`，首个为 lease owner，后续为 aliases；
- dequeue callback 返回 `{leaseTurnId, canonicalTurnId, hostTurnIds}`，而不是仅 `turnId`；
- dropped item 不建立 dispatched binding；merged waiter 绑定同一 canonical ID。

这一步是身份方案的前置不变量。若不先修，任何映射表都只是在记录一个可能不落盘的 UUID。

### 2.4 映射表归属与生命周期

映射表属于 `ClaudeTurnReconciliationCoordinator`，不是：

- `RuntimeTurn`：observer-only turn 不存在于 `runtimeTurns`；
- observer：host result 与 MessageChannel lease 不在 observer；
- feature/core：Claude transcript UUID 是 provider 私有事实；
- `ProjectionWriteCoordinator`：它只协调 UI 写。

索引：

- `byCanonicalId: Map<string, TurnRecord>`；
- `canonicalByHostTurnId: Map<string, string>`；
- `pendingNotificationClaimsByHostTurnId: Map<string, NotificationClaim[]>`。

清理：turn terminal 且两轨已收口后删除热记录，只保留有界诊断摘要；session generation 变化时整体失效。不得把该映射持久化为第二事实源；重启后由 bounded transcript recovery 重建当前 open turn。

## 3. mapper / observer 事件契约重划

### 3.1 mapper 只产“transcript 事实”

`ClaudeTranscriptTurnMapper` 不再自行判断“这一定是新 auto turn”。它为所有 queryable、非 sidechain、非 replay 的 user row 发出 `observed_start`：

```ts
type TranscriptTurnFact =
  | { type: 'observed_start'; identity: TranscriptIdentity; source; showUser; lineOffset }
  | { type: 'observed_chunk'; canonicalTurnId; identity: string; chunk; lineOffset }
  | { type: 'observed_terminal'; canonicalTurnId; terminalKind: 'result'|'end_turn_quiet'|'next_user'; lineOffset; metadata }
  | { type: 'observed_interrupted'; canonicalTurnId; reason; lineOffset? };
```

其中 `TranscriptIdentity` 至少含 `canonicalTurnId/transcriptUserId/sessionGeneration`。`started/chunk/finished` feature 事件改为 observer 对 coordinator verdict 的投影，不再由 mapper 直接决定。

`terminalKind` 显式保留证据等级：真实 result、quiet settle、next-user 隐式收口不能混成无来源的 `finished`。

### 3.2 coordinator 对 start 的裁决

coordinator 返回：

- `host_mirror`：canonical ID 已绑定 host dispatched turn。observer 不申请 auto lease、不新增消息、不计第二次完成；只补 transcript offset/terminal evidence。
- `external_new`：没有 host binding，来源属于 peer/channel/coordinator/notification。沿现有 FIFO promotion 建 auto lease。
- `embedded_external`：真实 external 输入发生于 host 活跃期间且产品语义要求嵌入；保留现有 embedded bubble，不另开 auto lease。
- `duplicate`：同 generation 已见同一 identity/event，丢弃。
- `conflict`：同一 canonical ID 绑定到不兼容 host turn/source；停止对该事件做完成/通知，记录诊断。若冲突影响 active host result 归属，进入 persistent query 重建，不靠 heuristic 猜。

### 3.3 镜像合并规则

1. **内容权威**：活跃 host turn 的实时内容以 SDK stream 为主；同 canonical ID 的 observer chunks 只做 fingerprint/完整性诊断并丢弃，不再写 ChatState。
2. **终结权威**：host 轮租约仍由 runtime result 正常收口；observer terminal 是归属证据和缺失检测，不直接越权释放 MessageChannel。
3. **observer-only 内容**：external/notification auto turn 仍以 transcript 为唯一内容源，沿现有 mapper → observer FIFO → feature projection。
4. **恢复**：crash/session restart 后没有活跃 host binding 的 open transcript turn，可按 bounded recovery 恢复为 external/replay；若 canonical ID 已由恢复上下文证明属于 host，则只恢复 binding，不再投影第二份。
5. **计数**：一个 canonical ID 最多产生一个 `CompletedTurnEvent`、一个通知决策、一个持久可见 user/assistant 对。

### 3.4 observer 职责保留

`ClaudeTranscriptTurnObserver` 继续负责：

- 单线程 consume chain；
- tail reset/recovery；
- quiet settle；
- auto FIFO promotion；
- callback timeout；
- host-cancel 后 dead auto turn 的确定性清理。

变化仅是 promotion 前先取 reconciliation verdict。`hostUserTranscriptIds` Set 与 `lastHostUserOffset` 迁入 coordinator 后删除，避免第二份身份状态。

## 4. notification result 归属状态机

### 4.1 数据结构

boolean 改为**每个 host canonical turn 的有序 claim 队列**，支持连续多个 notification：

```ts
type NotificationClaimState =
  | 'armed'
  | 'runtime_result_consumed'
  | 'orphan_evidence_seen'
  | 'rebuilding'
  | 'resolved';

interface NotificationResultClaim {
  claimId: number;                 // coordinator 单调序号，仅进程内
  hostCanonicalTurnId: string;
  notificationCanonicalTurnId: string;
  armedAtMonotonicMs: number;
  armedAtRuntimeSequence: number;
  state: NotificationClaimState;
  evidence?: 'runtime_result' | 'notification_terminal' | 'host_row_surpassed' | 'timeout_rebuild';
}
```

`notificationCanonicalTurnId` 必须来自 SDK notification user echo 的 UUID；拿不到 UUID 时不进入“猜下一 result”分支，直接记 `identity_missing` 并重建 persistent query。

### 4.2 转移

| 当前 | 事件 | 动作 | 下一状态 |
|---|---|---|---|
| 无 claim | 带 UUID 的 task-notification user echo，host lease 活跃 | 建 claim，记录 host/notification 双身份与 sequence | `armed` |
| `armed` 队首 | runtime `result` 先到 | 该 result 仅销该 notification claim；不 transform、不 settle host | `runtime_result_consumed → resolved` |
| `armed` | observer 看到同 notification canonical terminal，但 runtime result 尚未消费 | 证明两轨已分歧；冻结无身份 result 消费并请求重建 | `orphan_evidence_seen → rebuilding` |
| `armed` | observer 看到 owner host user row 已在 notification 后落盘，而 claim 未消费 | notification 已被 host row 超越；冻结并重建 | `orphan_evidence_seen → rebuilding` |
| `armed` | watchdog 到期 | 不把下一 result 判给任何轮；显式重建 | `rebuilding` |
| `rebuilding` | 旧 query 已关闭、相关 runtime turns 经既有 cancel/retry 收口，新 query ready | 清 claims；原 host turn按既有 crash recovery 复用同一 feature turnId/新 dispatch binding | `resolved` |
| 任意非 resolved | cancel/session switch/transcript replace | 取消 claim；沿既有 terminal path 清理 | `resolved` |

关键裁决：**observer 证明确有 orphan 时不只是清 flag 后继续吃旧 stdout**。旧 stdout 上仍可能迟到一个无身份 result；直接清除会把风险从“吞 host result”翻转为“迟到 notification result 提前结算 host”。因此先隔离并重建 persistent query，旧 stream 的迟到消息随 query teardown 丢弃。这比仅靠顺序清 flag更严格。

### 4.3 timeout

首值设为 **30 秒**，从 `armedAtMonotonicMs` 起算；使用 monotonic clock，不用 wall clock。

依据与边界：

- 已知错误样本的假完成约 4–5 秒；observer 固定 poll 与 quiet settle 合计通常约 2–4 秒。30 秒覆盖多个观测周期，不把正常数秒抖动当 orphan。
- timeout 不是“notification 应在 30 秒内完成”的业务假设；到期动作是安全重建，不是把下一 result 猜给 host。
- 该值必须进入诊断并在批1旁路采样后校准；不得做用户设置，也不得依据一次样本自动学习。
- 同 host turn 多 claim 共享最早 deadline；队首超时即重建整条 persistent query，因为后续无身份 result 序列已不可证明。

### 4.4 与 crash recovery 的关系

复用现有 `closePersistentQuery(..., {preserveHandlers:true})`、`lastSentTurnId`、`reRegisterTurnForRetry()` 与 history recovery，不新造第二套 replay。新增重建原因 `notification_attribution_lost`，并要求：

- 先把 coordinator 标为 `rebuilding`，再关闭旧 query，防止 teardown 中迟到 result 被消费；
- preserve 的 host turn沿原 feature `turnId` 重发，但获得新的 canonical transcript UUID；coordinator 将旧 binding 标 superseded，建立新 binding；
- 同一 recovery generation 最多自动重建一次；再次超时 fail-fast，向用户显示可取消/重试状态，避免无限重建。

## 5. 不变量清单

### 5.1 身份与对账

1. 每个实际送入 Claude harness 的 queryable user message恰有一个 canonical transcript UUID。
2. 一个 canonical ID 在同一 session generation 内只能绑定一个逻辑轮；一个逻辑轮可有多个 host aliases（queue merge）。
3. host candidate UUID 只有 dequeue 后才成为 dispatched binding，observer 命中后才成为 transcript-confirmed binding。
4. transcript UUID 只判身份；`lineOffset` 只判因果先后；时间戳不参与所有权。
5. 同 canonical ID 的 host/observer 镜像最多产生一次业务完成与一次可见投影。
6. 无身份或冲突 result 不得猜归属；涉及 active lease 时重建或显式失败。

### 5.2 MessageChannel 与 runtime

7. 同时最多一个 MessageChannel active lease；仍由 lease owner feature `turnId` 释放。
8. text merge/attachment replace 不改变 queue item canonical UUID；aliases 共享同一 settlement。
9. result 只有在 coordinator verdict 为 `settle_host` 时才能进入 `settleTurnAtResult()`。
10. notification claim 消费不得 transform usage 到 host turn。
11. cancel、close、handoff、retry 仍幂等；coordinator cleanup 先于 lease release，迟到事件因 generation/binding 失效被丢弃。
12. cold-start 不产生 notification claim；现有 fail-fast invariant 保留。

### 5.3 observer

13. observer consume 串行、auto FIFO 顺序、quiet settle 2 秒、callback timeout 与 `hostCancelled` 语义不变。
14. host mirror 永不申请 auto lease；external auto 才申请。
15. `finished → release → promote next` 顺序不变。
16. transcript replace/observer stop 对未完成 external turn仍发 interrupted cancel，不伪装 completed。
17. replay 以 canonical identity 去重；已有 host binding 只恢复证据，不重复内容。

### 5.4 feature 与投影

18. `ProjectionWriteCoordinator` 的 live/stored 共用 FIFO、锁顺序“business turn lease → live projection lease”、live release 后再排 stored，全部不变。
19. 对账只决定“该事件属于谁/是否镜像”，不跳过 auto 内容 save、finalize 或 lease release。
20. `supersededByHostUser` 在迁移期保留兜底；身份模式生效后只作为诊断，不再是主通知裁决。
21. save 失败仍不撤销已可见完成；finalize/reprojection 失败仍抑制 completion notification。

### 5.5 恢复与其他功能

22. ESC/cancel 必须最终释放 runtime、feature、projection 三类 lease，且每类至多一次。
23. crash recovery 使用同一 feature turn identity，但新 dispatch 可获得新 canonical UUID；旧 binding 明确 superseded。
24. compact boundary/session init/queue-operation 仍是 session/control facts，不创建业务轮。
25. peer/channel/coordinator external 输入保持现有可见标签与 embedded 语义。

## 8. 附录：rewind/fork 目标级预禁用

### 8.1 共享 vocabulary

```ts

  | { state: 'enabled'; canonicalTurnId: string; checkpointId: string }
  | { state: 'disabled'; reason: TargetDisabledReason };
```

# 风险与权衡

1. **上游事实并非正式 Claude Messages API 契约。** 本方案依赖 `@anthropic-ai/claude-agent-sdk`/Claude Code 的 SDK user UUID、origin、JSONL row 与 result 行为；这些是本地适配契约，不由公开 Messages API 保证。实施触发时必须先用当前 SDK 版本和真机 transcript 复验，不能只依赖类型声明。
2. **result 本身可能仍无 canonical identity。** 方案不伪造身份：正常时以带 UUID 的 notification echo 建有序 claim；一旦 transcript 证明序列分歧或超时，重建旧 query，绝不继续 FIFO 猜测。
3. **MessageChannel merge 是主要迁移风险。** 多个 feature turn 合成一个 SDK logical turn 时，业务上必须接受“多 alias 对一 canonical”；若未来产品要求每条发送各有独立轮，应该关闭 merge，而不是强造多个 transcript UUID。
4. **30 秒 timeout 是初始运维值。** 太短会增加安全重建，太长会延长卡顿；批1必须记录 arm→result/terminal 分位数再校准。无论数值如何，timeout 动作始终是重建，不是归属猜测。
5. **重建有用户体验成本。** 可能造成一次响应重放或延迟，但比静默错误通知、提前 settlement、永久 pending 更可控；同 generation 限一次，防循环。
6. **迁移期双逻辑会增加认知负担。** 只允许三种明确 mode，并给每批删除条件；不得长期停在 `enforce_with_fallback`。
7. **诊断隐私。** UUID/task ID/正文只存 salted hash或类别；沿用现有 128 KiB 双段轮转，不扩大为长期明文日志。
8. **不改 ProjectionWriteCoordinator。** 身份对账无法由 DOM FIFO 解决；把业务身份塞入该层会破坏其 provider-neutral 单一职责。

## 迁移/落地代价

这是结构性改造，预计跨 runtime、channel、transcript mapper/observer、feature event 与测试 fixtures；三批均需独立发布与真机观测。代价主要来自冻结并验证上游非正式 transcript 契约，而不是 coordinator 本身代码量。当前无复发、也无轮次生命周期新功能时保持 parked，不为“理论完整”主动扰动 3.1.1 生产。
