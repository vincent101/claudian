# 背景与问题

M1–M3、P0、P1 已解决超大 transcript 的索引、分页和全历史搜索，但分页仍以固定 50 turn 作为资源单位，导致 71–91 MB 乃至 1.59 GB 会话在首屏物化、JSON 解析和 Markdown/tool DOM 渲染阶段无上限占用主线程；同时索引预热与 lease 缓存路径分裂，重复重建并放大卡死。

# 方案设计

## 1. 路径选择与目标形态

### 1.1 方案对比

| 方案 | 内容 | 优点 | 缺点 |
|---|---|---|---|
| 务实止血 | 固定 50 turn 改为字节预算；巨型正文折叠；修缓存与 lease | 改动集中、最快恢复 | 继续累计 DOM；物化仍在主线程；资源边界分散 |
| 理想终态（采用） | 统一资源预算；索引规划、分块/后台物化、惰性正文、页面级 DOM 窗口、数据 LRU；分批上线 | 从 transcript 到 DOM 均有硬边界；71 MB、91 MB 与 1.59 GB 走同一路径；可持续扩展 | 跨 provider contract、投影、renderer 与 tab 状态，迁移成本高 |
| 全量预转换数据库 | transcript 预导入 SQLite/独立存储再查询 | 查询与分页能力强 | 引入第二事实源、同步和迁移复杂度过高，不符合当前需求 |

采用“理想终态、分批落地”。不回滚当前现网版本；各批在现网基线上独立构建、隔离验证、部署，失败只撤销本批产物。

### 1.2 不变量

1. transcript 仍是唯一历史事实源；索引、page cache、DOM 都是可丢弃投影。
2. turn 只表达语义边界，不再表达资源预算；所有入口同时受 `turn / source bytes / projected chars / DOM nodes / wall-time slice` 约束。
3. 首屏、加载更早、搜索定位、离屏搜索候选共用同一物化器；不得各自绕过预算。
4. 单个 turn 超预算不是失败：进入“巨型 turn 摘要投影”，禁止为了至少显示一 turn 而解除上限。
5. 折叠必须是惰性：collapsed 状态不得先生成完整 Markdown/tool DOM；展开才请求详细投影并可撤销。
6. lease 只管理活跃消费者；缓存管理已完成快照。`release()` 不得清全局缓存。

### 2.2 窗口规划

在索引上先倒序累计 turn 元数据，取同时满足所有预算的最大连续窗口。因此 71/91 MB 会话不会因 turn 数少而一次吃完整文件；普通小会话仍可在一次窗口内展示足够多 turn。

若最近 turn 本身超过预算：

1. 只读取构成可见摘要所需的 entry；
2. 文本块保留前后片段和原始字符数；tool result 只保留工具名、状态、输入/结果大小及小型摘要；附件/base64、thinking、原始大结果不进入 summary projection；
3. UI 显示“内容过大，展开加载”；展开走 `detail` 请求，但仍按块读取和渲染，不构造无界字符串或 DOM；
4. 搜索命中巨型 turn 时，按索引 `projectionKey` 定位到消息摘要；用户展开后才渲染完整命中附近内容。全历史命中计数继续来自 search sidecar，不依赖当前 DOM。

### 3.2 Worker 与降级

`worker_threads` 已实证在当前 Electron 运行时不可用，不能再次把它当唯一正确路径。执行器采用能力适配：

1. 隔离验证 Web Worker（自包含 bundle、消息传递仅含 entry descriptor 与投影结果）；通过 CSP、文件访问与大对象传输实测后启用。
2. Web Worker 不可用时，主线程执行同一状态机：每累计 `timeSliceMs` 或一个大 entry 后 `setTimeout(0)` 让出事件循环；不得回退同步整页循环。
3. Worker 和 direct-cooperative 必须跑相同 fixture 对拍；切换后端不改变结果和错误语义。
4. AbortSignal 贯穿计划、读取、解析、投影；tab generation 失效后停止剩余工作且不回写。

后台化只降低长任务，字节/字符预算才是内存边界；两者不得互相替代。

## 6. 分批实施顺序

### B1：秒开止血（优先，独立部署）

1. 红测固定 50 turn 在 71/91 MB fixture 超预算。
2. 增加 turn source-byte 聚合、`HistoryResourcePolicy`、预算窗口规划；首屏与“加载更早”改走预算窗口。
3. summary projection 与文本/tool 惰性 shell；渲染按帧分批，先不做完整 DOM 窗口。
4. 删除 shadow 分叉，统一 acquire；release 不清缓存；修 loadActive lease 所有失败路径。
5. 增加预算、物化、渲染、缓存诊断事件。

验收后 71.6/91.3 MB 会话冷索引完成后 2 秒内出现可读首屏；缓存命中再次打开 2 秒内出现首屏；1.59 GB 会话索引阶段保持可交互，索引完成后 2 秒内出现有界首屏。不得再出现 50 turn 物化 100–500 MB。

### B2：分块/后台物化（独立部署）

抽出增量 materializer 与 executor；先完成 cooperative direct，再以相同协议接 Web Worker。验收主线程单任务 p95 < 50 ms、心跳不断档、结果与旧小会话全量投影逐 ID/正文/tool 状态对拍。

### B3：页面级 DOM 窗口与数据 LRU（独立部署）

引入 page store、spacer、可见页 pin、加权 LRU、展开态恢复。验收连续浏览 20 页后 DOM turn ≤200，page data ≤32 MiB（固定页除外并单独计量），往返锚点误差不超过一个可见行，搜索定位可穿越已淘汰页。

### B4：资源预算收口（独立部署）

所有历史入口切到统一 policy；删除 UI 对裸 `loadRange(50)` 的调用；完善内存压力主动回收、诊断面板与 benchmark。保留 `loadRange` 仅供独立全量导出，且导出必须流式消费，禁止回写 UI state。

依赖顺序：`B1 → B2 → B3 → B4`。每批红测、定向绿测、全量门、隔离 vault 真机、独立构建部署；不得跨批夹带。

# 风险与权衡

1. **Worker 可用性未知**：`worker_threads` 已失败，Web Worker 必须先隔离探针；正确性和资源边界不能依赖 Worker，cooperative backend 是正式后端而非临时 fallback。
2. **“完整展开”仍可能巨大**：detail 不是一次性全展开，而是块级继续加载；否则只是把首屏卡死移到按钮上。
3. **搜索与截断投影**：索引计数可能命中 summary 未展示部分。UI 应显示命中存在并引导加载对应 detail，不能降低全历史计数或伪造 DOM 高亮。
4. **spacer 高度漂移**：异步 Markdown、图片和字体会改变高度。只在渲染稳定后记录，ResizeObserver 持续修正；锚点以稳定 message ID 二次校准。
5. **缓存内存核算**：JS 对象真实堆占用高于字符串字节。权重为保守估算，B4 需用 Electron heap/RSS 校准；诊断同时记录估算值与 process memory。
6. **多 tab 与刷新竞态**：page store 必须 per-tab；索引 snapshot 可共享。新 snapshot ready 前旧 lease 和旧 pages 保持可用，成功后原子切换。
7. **迁移/落地代价**：需把现有 flat `messages/loadedRanges` 演进为 page store，并拆开 native materialization 与渲染；B1 先建立兼容适配，B3 再移除 flat 主路径。代价不改变终态边界。
8. **预算默认值需实测校准**：8 MiB、2 Mi chars、32/128 MiB 等是首轮安全基线，不宣称普适；只有 71.6 MB、91.3 MB、1.59 GB 三档隔离实测均通过后才能固化。

需用户在实施前确认的产品语义仅一项：巨型正文展开采用“分块继续加载”而非“一键完整加载”。本方案推荐前者；后者违反端到端资源预算，不应提供。

# 验证方式

## 自动测试（TDD）

1. **窗口规划**：50 个小 turn、单个 12 MiB turn、尾部 3 个合计 20 MiB、跨 segment；断言实际 range 同时满足 turn/byte/char 预算，巨型 turn 返回 summary 而非空页。
2. **物化峰值结构**：spy 证明不再调用整页 `readIndexEntries(entries[])`；entry 逐条释放，tool associations 去重且单次读取；abort 后无后续 read/回写。
3. **lease**：`ready` reject、window load reject、generation 失效、renderer reject 均恰好 release 一次；成功转交 state 后不提前 release。
4. **缓存**：oversize hydration + active acquire 只构建一次；release/reopen 命中；关闭 A 不清 B；snapshot append/replacement 只失效对应 path；加权 LRU 不逐出 protected/in-flight。
5. **惰性渲染**：collapsed 大文本不调用 Markdown renderer；collapsed tool 不调用 `renderExpandedContent`；首次展开调用一次，重复展开复用，淘汰后可重建；复制不会返回截断文本。
6. **分片调度**：合成重渲染任务跨至少两个 yield，首片完成前不宣称 page complete；中间单条失败不阻断后续。
7. **DOM 窗口**：20 页后 turn 上限、spacer 高度、上下往返、展开态、可见页 pin、LRU 淘汰、搜索定位重物化。
8. **正确性对拍**：小/中 transcript 完整翻页后的 message ID、正文、tool 状态、branch、搜索结果与现有基线一致。

## 性能与真机验收

在隔离 vault 使用脱敏副本：71.6 MB、91.3 MB、1.59 GB，以及一个普通小会话。记录 shell 首帧、索引耗时、index cache hit、计划字节、实际 read bytes、物化耗时、首条消息可见时间、每帧 Long Task、DOM turn、page/index cache weight、Renderer RSS/heap。

验收门槛：

- shell 先可交互；索引/物化期间诊断心跳持续。
- 71.6/91.3 MB 冷开与缓存重开均在 2 秒内出现可读首屏。
