## 背景与问题

审查 `5cb8799d..e530193d` 的跨改动交互，重点验证超大会话预算化是否破坏流式、历史、Provider 与恢复链路。

## 方案设计

### 维度一：既有功能

- 流式/Cmd+F → **异常（高）**：READY 早于分帧队列排空；此时发送会把实时消息追加到尾部，旧队列随后继续追加，顺序错乱。流式中定位未加载命中还会 `renderMessages` 清空 DOM，`currentContentEl` 继续指向脱离节点，后续增量不可见（`MessageRenderer.ts:261-361`；`InputController.ts:353-376,458`；`ConversationController.ts:529-570`）。
- rewind/fork → **异常（中）**：ID/原生 resume 锚点仍可用，但 rewind 输入预填直接取摘要 `content`；巨型用户输入会被截断。fork 的内存前缀同样是当前摘要窗口（`ConversationController.ts:778-830`；`Tab.ts:1078-1107,1128-1158`）。
- Codex → **正常**：无 `loadWindow/acquireHistoryIndex`，仍走原 hydration；共享渲染支持其 contentBlocks/toolCalls。projection 通知只驱动搜索，不触碰 inline plan approval（`CodexConversationHistoryService.ts:27-140`；`ConversationController.ts:321-387`；`MessageRenderer.ts:544-604`）。
- SDK amnesia → **异常（高）**：C6 已存在，优先调用 full exporter；但 exporter 仍 `loadRange(0,total)`，1.59GB 会无界物化，恢复本身可能再次卡死/OOM（`ClaudeChatRuntime.ts:1687-1689,1751-1757`；`ClaudeConversationHistoryService.ts:816-825`）。
- 复制/导出 → **异常（高）**：复制摘要属已知妥协；全量导出无预算保护，同上（`MessageRenderer.ts:480-486,630-672`；`ClaudeConversationHistoryService.ts:816-825`）。
- 多 tab 同会话 → **正常，需压力观察**：ref 计数和旧快照回滚成立；force-new 仅让其他 tab 暂持旧快照，不泄漏（`ClaudeConversationHistoryService.ts:520-575`；`ConversationController.ts:504-526`）。
- 切换/保存/标题 → **正常**：每次调度重置 queued，READY 清空；ERROR retry 重入 SCHEDULED，无永久 placeholder（`TabManager.ts:350-429`；`Tab.ts:1663-1674`）。
- inline edit/image/canvas → **正常**：改动仅存量消息渲染；单消息 catch 会清半成品并隔离错误（`MessageRenderer.ts:428-513`）。
- 命令目录 → **正常**：READY oversize 回退当前内存快照，冷 tab 非 READY 仍走 sync 快照（`TabManager.ts:1022-1057`）。
- TurnObserver/tail → **正常**：READY 前创建 runtime，并从 snapshotOffset 起观测；blocked shell 不启动（`TabManager.ts:383-409`；`Tab.ts:577-591`；`ClaudeChatRuntime.ts:2438-2473`）。

### 维度二：推演风险（高→低）

1. **高**：三重预算并非硬约束。anchor 豁免可使单 turn 投影超过 `maxProjectedChars`；`timeSliceMs` 完全未用于物化（`ClaudeConversationHistoryService.ts:741-793`）。
2. **高**：流式与存量分帧缺少统一 generation/排空门禁，见维度一。
3. **高**：B4/完整历史恢复未预算化，见维度一。
4. **中**：`around/newer` 物化统一 newest-first；多 turn around 若字符超限会保留窗口新端而非中心锚点，契约语义不稳（`HistoryWindowPlanner.ts:76-113`；`ClaudeConversationHistoryService.ts:758-793`）。
5. **中**：completed LRU 超过 2 且全受保护时仍回退驱逐受保护项，不泄漏但会在 ≥3 活跃大会话间反复重建（`ClaudeTranscriptHistoryIndex.ts:331-358`）。
6. **低**：摘要/detail 的真实 UUID 通常稳定；但首条超大 assistant 被跳过时 synthetic marker ID 与索引 projectionKey 不同，搜索会显式 projection_mismatch，不会误定位（`HistorySummaryProjection.ts:121-158`；`sdkMessageParsing.ts:233-245`）。
7. turn model 快照与 fork/amnesia 语义正常：快照仅用于 usage 分母，不改变恢复/分叉模型（`ClaudeChatRuntime.ts:1730-1737`；`transformClaudeMessage.ts:159-216`）。

**总体：需补修，不回滚。** 阻断上线项无；生产继续使用前至少修复“流式×分帧/搜索重渲染”和“full export/amnesia 无界物化”，随后收紧 anchor 投影硬上限。

## 风险与权衡

预算化 UI 主路径有效，但完整历史消费者仍绕过预算；当前最危险的是低频恢复/导出触发资源灾难，以及用户在首屏仍分帧时立即发送或搜索造成静默 UI 失联。

## 验证方式

1. 1.59GB 会话首屏未排空立即发送，再 Cmd+F 定位未加载 turn；核对消息顺序、增量可见性。
2. 模拟 amnesia 与导出，采集 RSS/耗时，确认不再一次性 `loadRange(0,total)`。
3. 构造单 turn 投影 >2M 字符、3 个并行活跃大会话，核对预算与 cache rebuild 次数。
4. 已跑聚焦单测：4 suites / 491 tests 全通过；需补上述交叉集成测试。
