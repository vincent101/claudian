# 背景与问题

生产版已打通超大会话索引、分页和全历史搜索，但真机暴露索引不可观测、搜索定位身份不稳定、交互不闭环及 hover 时间漏做。

# 方案设计

## 1. 1.53 GB 首屏未出

`ClaudeTranscriptHistoryIndex.ts` 在 Electron 不支持 Worker 后进入全进程单并发 `directBuildTail`。每 1 MiB 虽让步，但每行仍同步解码、`JSON.parse`、提取搜索正文，之后还有 branch finalize；Node 8.3 秒不能按固定系数推算 Electron。8 分钟可能是排队、极慢或 promise 未决，现日志无法区分，暂不能认定卡死。UI 只有 `Tab.ts` 的“正在加载会话…”，无阶段/进度，半分钟无反馈是确定缺陷。

修复：诊断增加 `queued/start/progress/finalize/complete/failed/aborted/stalled`，记录匿名 build ID、worker/direct、排队/运行耗时、bytes/total、entries/turns、错误名；progress 每 2 秒或 5% 节流，30 秒无推进只报警不强杀。将 `HistoryLoadProgress` 经 provider 分页接口传至 tab，显示“等待索引/建立索引 37%/整理索引/加载最近 50 轮”，失败可重试。涉及 `src/core/providers/types.ts`、Claude history 两文件、`ConversationController.ts`、`Tab.ts`、i18n。

最小真机取证：①tab 当前文案截图；②DevTools 首个 error/stack；③等待 1 分钟时 Obsidian Helper(Renderer) CPU、内存、磁盘读数；④事后 `history-index.current/previous.jsonl`。CPU 高且进度增长=慢；CPU 低且 queued=排队；无推进未结束才查死锁。

## 2. 连续 50+ 页

静态推演正确：旧 cursor 单次消费，`endTurn-50` 生成新 cursor；失败恢复；UI 按 message id 去重；tool 跨页关联补读；prepend 以原首条消息校正锚点。风险是约 2500 turn 全驻状态和 DOM，Markdown/tool 越多越慢，异步渲染还可能令锚点漂移。

用户核对：页首时间持续变早、按钮最终消失、随机首尾句搜索唯一命中、tool 不永久 running、加载前后视口不跳。日志增加每页 cursor、turn 范围、返回/去重数。20 页后若明显退化，启动 M5 按页窗口化（DOM 保留 150–250 turn），不再无限堆积。

## 3. 搜索交互（P1 修订规格）

### 3.1 用户交互与状态机

- 交互保持不变：当前 tab 的平台快捷键打开单行浮层 `输入框 | 当前/总数 | ↑ | ↓ | 关闭`；直接高亮正文，默认选最新命中；↑/Shift+Enter 向更早、↓/Enter 向更新滚动，边界不循环。
- 状态为 `closed → idle → indexing | searching → ready | empty | error`，`ready → locating → ready | error`。空查询回 `idle` 并清 mark；输入防抖 300 ms。每次输入、关闭、切会话递增 `generation`，仅同代异步结果可提交。
- `indexing/searching/locating` 禁用导航、允许关闭；索引中显示“索引中”，完成后若 tab、会话、query、generation 均未变则自动查询。失败保留 query 与原当前项。
- Command+F、焦点恢复、Esc 仲裁依赖已先行的③⑤批：document capture 仅命中 active Claudian tab；显式关闭恢复打开前焦点，生命周期关闭不抢焦点。P1 只接入其公开 open/close/active 契约，不重复实现。

## 4. in-place 搜索（P1，删除结果列表）

P0 `projectionKey` 只解决消息身份；P1 以“索引定全局顺序、DOM 定实际 Range”为边界，不把 Markdown 源偏移直接用于渲染 DOM。

### 4.1 结果枚举与可见文本投影

- `SearchHit = { turnIndex, projectionKey, matchOrdinal, matchedText }`，不携分页 cursor。索引对每个 corpus item 按源顺序循环 `indexOf`，命中后从 `matchStart + needle.length` 继续，即**非重叠、大小写不敏感**；空 needle 不枚举。`matchOrdinal` 在同一 `projectionKey` 内跨 corpus item 连续递增。最终稳定排序 `(turnIndex, projectionKey, matchOrdinal)`，不得依赖 Map/segment 插入顺序。
- 统一“可见文本投影”：可搜索范围仅消息内 `.claudian-text-block`。深度优先遍历可见文本节点，排除 toolbar、按钮、时间、隐藏节点及 `aria-hidden=true`；`<br>` 投影为 `\n`。段落、标题、引用、代码块、列表项之间投影为 `\n`；相邻表格单元格投影为 `\t`、行间为 `\n`。分隔符没有 DOM Text 锚点且命中不得跨越它，因此两个块、列表项或单元格不会拼成伪命中；行内 `<em>/<a>/<span>` 不插分隔符。投影保留每个字符到 `(Text, offset)` 或“不可跨分隔符”的映射。
- 索引层继续保存流式构建的**规范化 Markdown 搜索语料**，维持 Worker/无 DOM 路径；不得在全量索引阶段调用 `MarkdownRenderer`，也不要求索引语料与渲染可见文本全文逐字同构。索引只负责筛出候选消息、生成候选命中 ordinal 和全局顺序，不提供 DOM offset。
- `projectVisibleText(root)` 仅负责已渲染 DOM 的实际坐标。`enumerateVisibleMatches(root, query)` 基于该投影按同一非重叠规则重匹配，跳过跨不可跨分隔符的候选；索引命中提交为结果前，必须能映射到目标 DOM 的对应 ordinal。一次重施先基于原始 Text 节点计算该消息**全部** Range/分段锚点，再按 DOM 逆序包裹 mark，防止先拆 Text 使后续坐标失效；允许跨行内节点，禁止 `innerHTML` 或拆/重建代码块、表格、链接结构。
- 对已加载候选直接以现场 DOM 校验 ordinal；对未加载或规范化语料存在多命中歧义的候选，仅在搜索时按需用实际 `MarkdownRenderer` 离屏渲染**该候选消息**，复用 DOM 投影校准命中并按 `projectionKey + contentHash` 缓存，搜索结束可按 LRU 回收。候选按需渲染失败或目标 ordinal 不存在时，结果标记 `projection_mismatch`；导航时显示可见错误并记录诊断，禁止静默跳过或退回源码偏移猜测。

### 4.2 per-tab loaded ranges 与无状态区间加载

- `LoadedTurnRange = { start: number, end: number }`，半开区间、按 start 排序、重叠或相邻即合并；`TabHistoryState.loadedRanges`、消息集合与普通分页 frontier 属于 tab，不放进会话级索引。
- provider 不再暴露/保存 page cursor、search cursor 或 `searchCursors`。lease 提供无状态 `loadRange(startInclusive, endExclusive): Promise<{ range, messages }>`；边界必须满足 `0 ≤ start < end ≤ lease.totalTurns`，返回固定快照上的精确区间。`SearchHit.turnIndex` 是定位唯一输入。
- 初始页调用 `loadRange(max(0,totalTurns-pageSize), totalTurns)`；搜索定位调用覆盖目标 turn 的一页区间；普通“加载更早”由 tab 依据 ranges 计算区间。结果并入 ranges，DOM 按 `turnIndex` 插入并按消息 ID 去重，已加载区间永久可达。
- 普通“加载更早”从包含 `totalTurns-1` 的连续区间向前：优先请求它与下一个较老 range 之间最近的缺口，直至合并；无较老 range 才请求该区间之前一页。远距定位不改变该计算。定位只调用一次 `loadRange`；失败不改 ranges/current。
- 每次 ranges 变更后派生 `hasMore = ranges` 是否覆盖 `[0,lease.totalTurns)`。并发请求按 tab + range 共用 in-flight promise；迟到响应可并入该 tab ranges，但不得改失效 generation 的搜索 UI。

### 4.3 会话级索引共享、lease 生命周期与双 tab 隔离

- `HistoryIndexLease = { conversationId, totalTurns, ready, search(query), loadRange(start,end), release() }`。`totalTurns` 来自 lease 创建时的索引固定快照，在 lease 生命周期内不随 transcript 增长；新增完成态由重建/换取新快照后重搜体现。`acquireHistoryIndex(conversationId)` 共享同一 index、build promise 和 AbortController并增加引用计数；重复 Cmd+F 复用 `ready`，不得中止重建。
- lease 生命周期绑定“tab 正在展示该会话”的全程：会话装载时 acquire，切会话或关 tab 时 release；打开/关闭搜索面板不 acquire/release，故关搜索后普通分页仍受索引与 transcript protection 保护。引用计数归零才 abort 未完成 build、解除保护并允许 LRU 回收；`release()` 幂等。
- 每个 tab 持有自己的 lease handle、loadedRanges、搜索 generation/current 与 range 请求表。两个 tab 可引用同一固定索引快照，但任一 tab 的关闭、分页、定位均不得改变另一 tab 状态。

### 4.4 render hook 与 mark registry

- `MessageRenderer` 增加唯一聚合入口 `renderMessageContent(projectionKey, jobs)`：一条消息先收集其全部正文 `renderContent()` Promise，stored、prepend、live user update、stream-complete 四条路径均调用该入口；待 DOM 已提交且 `Promise.all(jobs)` 全部 resolve 后，仅触发一次 `onMessageContentRendered(projectionKey)`。任一正文失败则整条消息不通知并走既有错误路径；禁止每个 text block 分别通知、禁止 MutationObserver。
- fire-and-forget 仅允许发生在聚合入口外层；入口内部必须持有全部 Promise。prepend 在 fragment 插入真实 DOM 后才允许发 message-complete；stream-complete 必须覆盖最终 Markdown 替换，而非 partial update。
- `HistorySearchController` 维护 `MarkRegistry: Map<projectionKey, { generation, marks: HTMLElement[] }>`。收到一次 message-complete hook 时，若搜索仍 active 且 generation 相同，先清该 key 旧 mark，再按当前 query 对整条消息重施；关闭/换 query 清全表。当前命中以 `(projectionKey, matchOrdinal)` 重建 `.is-current`，缺失即显式错误。
- 查询成功默认选择排序后最后一项；仅对已加载 ranges 施加普通 mark。导航到未加载项时先定位页，等待对应 render hook 完成，再切 current 并 `scrollIntoView({block:'center'})`；不得用定时器或逐页递归猜渲染完成。

### 4.5 streaming、i18n 与依赖边界

- 搜索结果采用**完成态快照**：进行中的 assistant partial 不入结果、不高亮；收到 stream-complete render hook 后，对仍 active 的相同 query 开启新 generation 自动重搜。若原 current 三元组仍存在则保持，否则选最新；计数一次性替换，避免边流边跳。
- 保留 `chat.search.placeholder/noResults/error/resultCount`；新增 `previous/next/close/searching/indexing/locating/retryError`，10 个 locale 补齐；按钮使用本地化 `aria-label/title`。
- hover 时间由③⑤先行批实现：P1 仅保证可见文本投影排除其 toolbar/timestamp，不再设计或改造时间组件。

### 4.6 实施顺序（审核指定）

1. 结果多命中枚举与可见文本投影。
2. loaded ranges、会话索引 lease/引用计数及双 tab 隔离。
3. render-complete hook、Range 高亮和 mark registry。
4. 接入已完成的快捷键、焦点恢复、Esc 契约（③⑤依赖）。
5. 接入已完成的 message toolbar/timestamp，并验证排除搜索投影（③⑤依赖）。
6. streaming 完成态重搜、共享 build promise 与“索引中”自动查询。

# 风险与权衡

不以固定 Electron 劣化倍数或未取证硬超时下结论。in-place 牺牲摘要总览，但避免两套选中状态。DOM 可见投影比复用源码 offset 多一次文本遍历，却是 Markdown 正确性的必要成本；仅对已加载 DOM 分批施加 mark，不改变全历史计数。共享索引需严格引用计数，单测必须覆盖重复 release 与 build 中归零。索引投影和 DOM 投影若漂移选择显式失败，不做模糊降级。窗口化影响展开态与锚点，仍独立交付。

# 验证方式

1. 自动测 direct 排队、节流进度、成功/失败/取消/stalled，日志同 build ID 有始有终；1.53 GB 隔离副本逐阶段显示“等待索引 / 建立索引 N% / 整理索引 / 加载最近 50 轮”，半分钟内持续有可观察反馈。
2. 在用户已测试的 `notevault-33 · d8912b5b` 重做 50+ 轮核对：页首时间持续变早、按钮最终消失、随机首尾句搜索唯一命中、tool 不永久 running、加载前后视口不跳；并与全量 ID 序列对拍。
3. 搜索单测：同一 projection 三次命中及相邻/重叠规则；大小写；行内 `<em>/<a>` 可跨节点；`<br>`、段落、列表项、表格单元格不得跨分隔符伪命中；代码块/表格元素树不变；toolbar/timestamp/隐藏节点不入投影；索引构建保持 Worker/无 DOM；已加载候选用现场 DOM 校验，未加载或歧义候选才按需离屏渲染且缓存命中；ordinal 不可映射时可见 `projection_mismatch`；同消息多命中先全算 Range、逆序 mark 后均可导航。
4. 分页与生命周期：provider 无 page/search cursor 状态；`loadRange` 边界与精确返回；远距定位后连续“加载更早”补齐中间缺口且 ranges 最终覆盖 `[0,totalTurns)`；定位失败 ranges/current 不变；搜索面板关闭后仍可普通分页；两个 tab 交叉 acquire/release、重复 release、build 中最后引用释放，一 tab 关闭不影响另一 tab。
5. 渲染与状态：stored/prepend/live user update/stream-complete 各自验证“一消息多正文 Promise 全成功仅通知一次、任一失败零通知”；prepend 必须插入真实 DOM 后通知；通知后 mark 仍在；旧 generation hook 不回写；索引中多次 Cmd+F 只有一个 build，完成自动查询；流式 partial 不计数、complete 后基于新固定快照重搜且 current 保持/按规则回落；视图外快捷键、连续 Esc、生命周期关闭依赖③⑤回归通过。
6. 时间覆盖由③⑤批测试承担；P1 追加断言 timestamp/toolbar 不进入可见文本投影。执行 `npm run typecheck && npm run lint && npm run test -- --selectProjects unit && npm run build`；重点补 `HistorySearchController.test.ts`、`MessageRenderer.test.ts`、`ConversationController.test.ts`、Claude history service 测试及 `Tab.test.ts`。
