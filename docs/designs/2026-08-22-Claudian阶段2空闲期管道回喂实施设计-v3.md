# Claudian 阶段 2 空闲期管道回喂实施设计 v3

> 已被 [[2026-08-22-Claudian阶段2空闲期管道回喂实施设计-v4]] 替代。v4 统一两层 turnId，修正完成/取消放行顺序，并闭合 conversation 单写者 ownership 转交状态机。

## 背景与问题

阶段 2 要在不改变阶段 1“task-notification 是终态权威销账信号”的前提下，让用户轮、通知自动唤醒轮和 Stop hook block 续轮共享同一套 turn 所有权、状态处理与渲染逻辑；v3 收敛 v2，补齐 MessageChannel 外部轮占用、可实现的 restart/cancel 语义和 conversation 单写者保存协议。

## 方案设计

### 1. v2 → v3 变更点

| 二轮复核项 | v3 定案 |
|---|---|
| auto lease 未进 MessageChannel | `ClaudeMessageChannel` 增加 `beginExternalTurn(turnId)`；user dequeue 与 auto start 共用唯一 `activeTurnId`，`completeTurn(turnId)` 统一核验和放行。 |
| 跨 Query preserveTurn 不可实现 | 删除跨 Query 无损续流。collecting/projecting 期间把 config restart 标为 deferred，turn settled 后执行；强制 session switch/cleanup 则 cancel，后续靠 transcript hydration。仅 user turn 零 chunk crash recovery允许重启并重放原消息。 |
| 多 tab revision 仍会覆盖分叉 | 不引入 registry。由 plugin 实例持有 conversation 级单写者锁；同 conversation 只有 owner tab 可产生 turn/保存，其他 tab 为只读镜像，发送先排队等待 ownership。锁为 plugin 级，跨 view 生效。 |
| save 全字段未闭合 | 定义完整 `ConversationSaveSnapshot`、字段 merge 规则和所有 save call-site 迁移表；session invalidation 改为 runtime 原子事件随 snapshot 提交，不再在 save 时破坏性 consume。 |
| notification / auto-start 顺序 | 固定 `ensure auto turn + MessageChannel.beginExternalTurn → 同步 onAutoTurnStarted → dispatchTaskNotification → return`；仍早退于 transform。 |
| cancellation 契约不足 | 定义 `cancelTurn(turnId, reason)`、queued/canonical merged waiter 的退出、destroy 时全量结算；所有 generator 必达 done/error。 |
| S4 依赖 S5 | S1–S3 可独立上线；S4（回喂）与 S5（usage/save/完成协议）合并为一个不可拆上线单元。 |

v2 §2 的 turn 对象化主体、§3 feature 仲裁、§5 domain/DOM 解耦继续成立；以下只给最终可实施形态。

### 2. Runtime turn 与 MessageChannel

#### 2.1 RuntimeTurn

在 `/Users/vincentwang/Documents/NoteVault/tools/claudian/src/providers/claude/runtime/types.ts` 定义：

```typescript
type RuntimeTurnKind = 'user' | 'auto';
type RuntimeTurnPhase = 'queued' | 'collecting' | 'projecting' | 'settled' | 'cancelled';

interface RuntimeTurn {
  id: string;
  kind: RuntimeTurnKind;
  phase: RuntimeTurnPhase;
  generation: number;
  chunks: StreamChunk[];
  metadata: ChatTurnMetadata;
  bufferedUsage: Extract<StreamChunk, { type: 'usage' }> | null;
  streamState: TransformStreamState;
  usageState: TransformUsageState;
  sawStreamText: boolean;
  sawStreamThinking: boolean;
  receivedChunk: boolean;
  abortController: AbortController;
  waiters: Set<ResponseHandler>;
}
```

删除 `ClaudeChatRuntime` 的全局 `_autoTurnBuffer`、`_autoTurnSaw*`、`turnMetadata`、`bufferedUsageChunk`、`streamTransformState`、`usageTransformState`。所有 transform、usage、metadata、dedup 操作显式传当前 turn。

#### 2.2 MessageChannel 唯一占用表

改造 `/src/providers/claude/runtime/ClaudeMessageChannel.ts`：

```typescript
private activeTurnId: string | null;
enqueue(turnId, message): EnqueueResult;
beginExternalTurn(turnId): void;
completeTurn(turnId): void;
cancelQueuedTurn(turnId): boolean;
cancelAll(reason): string[];
```

行为：

- user turn 仅在消息被直接交付给等待 consumer，或 `next()` 从 queue 取出时设置 `activeTurnId=turnId` 并同步触发 `onTurnDequeued(turnId)`。
- auto turn 在 transform 前调用 `beginExternalTurn(autoTurnId)`；仅当 `activeTurnId===null` 成功，否则 fail-fast，禁止覆盖 user turn。
- `completeTurn(turnId)` 仅接受相同 activeTurnId；清占用后交付下一 queued user turn。
- queue item 保存 `{turnId, message}`。文本合并时首项 turnId 为 canonical；`EnqueueResult` 返回 canonicalTurnId，后加入 query 的 handler 加入 canonical `RuntimeTurn.waiters`。
- `cancelQueuedTurn()` 从 queue 删除指定 turn，并返回是否删除；由 runtime 结算其全部 waiter。
- `close()` 返回全部 active/queued turnId，由 runtime 逐一 cancel，不能只清数组。

#### 2.3 route 顺序

`ClaudeChatRuntime.routeMessage()` 固定：

1. 若没有 channel active turn：创建 auto `RuntimeTurn`，调用 `messageChannel.beginExternalTurn(turn.id)`。
2. 同步调用 `onAutoTurnStarted({turnId,generation})`；该回调只取得 feature 排他 lease，不做异步渲染。
3. 调 `dispatchTaskNotification(message)`；命中则早退，不 transform。
4. 非通知消息用 active turn 自有 transform state 转 chunk，投给 user waiters 或 auto chunks。
5. `result`：user turn结算 handlers；auto turn await 完整 projection；最后 `completeTurn(turn.id)`。

这样通知依旧早退于 transform，但不会早于 feature 排他权。

### 3. Feature 排他仲裁

在现有 `/src/features/chat/controllers/InputController.ts` 内实现 turn 仲裁状态，不新建组件：

```typescript
private activeFeatureTurn: {
  turnId: string;
  kind: 'user' | 'auto';
  generation: number;
  conversationId: string | null;
} | null;
```

新增私有方法 `beginFeatureTurn`、`isCurrentTurn`、`finishFeatureTurn`、公开 `cancelTurnProjection(turnId)`。

- `onAutoTurnStarted` 同步调用 `beginFeatureTurn(auto)`，原子设置 `state.isStreaming=true`。
- `sendMessage()` 开头若已有 activeFeatureTurn，只执行现有 UI `queuedMessage` 合并和清输入框，不创建消息/DOM，不调用 runtime.query。
- 用户正常发送在创建 user/assistant DOM 前 `beginFeatureTurn(user)`。
- finish 后才 `state.isStreaming=false` 并 `processQueuedMessage()`。
- auto 与 user 共用同一 `currentContentEl` 的前提是 feature lease 排他；禁止无 lease 写这些字段。

### 4. restart 与 lifecycle

#### 4.1 restart 定案

`applyClaudeDynamicUpdates()` 的 restart 请求不再立即 `ensureReady(force)`：

- active turn 为 `collecting` 或 `projecting`：保存最新 `deferredRestartConfig`，本轮继续使用旧 Query；settled 后执行一次最新配置 restart。
- 无 active turn：立即 restart。
- user turn、`receivedChunk=false`、consumer 异常：保留现有单次 crash recovery，重建 Query 后重放 `lastSentMessage`；该 user RuntimeTurn 与 waiters 可保留。
- 任意已收 chunk turn：不声称续流。transport 崩溃则 `cancelTurn`；若会话继续使用，下一次 hydration 从 transcript 重建已持久化部分。
- session switch、reset、cleanup、tab destroy：强制 cancel，不延迟。

`closePersistentQuery()` 不再有泛化 `preserveTurn`；只保留窄化的 `preserveZeroChunkUserReplay` 内部参数，调用点仅 crash recovery。

#### 4.2 cancel API 契约

`ClaudeChatRuntime` 新增内部 `cancelTurn(turnId, reason, error?)`：

1. `phase=cancelled`、generation++、abort turn controller。
2. 若 queued：`MessageChannel.cancelQueuedTurn(turnId)`。
3. 若 active：停止该 turn 投递；调用 `MessageChannel.completeTurn(turnId)` 放行下一条。
4. 遍历 `waiters`：普通取消调用 `handler.onDone()`；异常调用 `handler.onError(error)`；随后清空。保证每个 `queryViaPersistent()` generator 退出。
5. auto turn 调 feature `onAutoTurnCancelled(turnId,generation)`；feature 仅清该 lease 创建的临时 state/DOM，不保存。
6. 删除 RuntimeTurn。

canonical merged lease：每个被合并 query 的 handler 都在 canonical turn `waiters`；result 时全部 `onDone()`，cancel 时全部 done/error。不得只结算 canonical 创建者。

`cancel()`：取消 active turn；不默认清 queued user turns。`resetSession()`、`setSessionId()`、`cleanup()`、`destroyTab()`：调用 `cancelAllTurns(reason)`，active + queued 全部结算。close/restart 若非 crash replay，同样全量结算。

### 5. Turn-scoped StreamController 与 DOM 解耦

沿用 v2 §5，但不新增 controller/service。直接在 `/src/features/chat/controllers/StreamController.ts` 增加 `TurnProjectionContext` 参数，替代数据层对 `ChatState.current*` 的隐式依赖。

- text：先写 `message.content`/context text buffer，再可选 DOM。
- thinking：先写 context thinking buffer；finalize 必写 `contentBlocks`，再可选 DOM。
- notice/error：先转为消息 text block，再可选 DOM。
- tool：先写 `toolCalls/contentBlocks` 和业务状态，再可选 DOM。
- usage：只写 turn 捕获的 conversation state，不依赖 DOM。

`SubagentManager` 沿用 v2 domain-first 拆分：

- sync/async `SubagentInfo` map 是真相；DOM state map 仅投影。
- `handleTaskToolUse(..., parentEl:null)` 仍创建 domain record。
- `renderPendingTaskFromTaskResult()` 无 DOM 时仍推断 mode、创建 record并处理 result，不得因 `targetEl` 为空 return。
- `updateAsyncDomState()` 收窄为可选 projector；无 DOM 不影响 transition/onStateChange。

### 6. conversation 单写者与保存语义

#### 6.1 plugin 级单写者锁

不引入 v2 的 registry。直接在 `/src/main.ts` 的 plugin 实例维护：

```typescript
conversationWriters: Map<conversationId, { tabId: string; queue: Promise<void> }>;
```

由 `TabManager` 调用 plugin 方法 acquire/release：

- 首个打开/开始 turn 的 tab 成为 writer。
- 同 conversation 的其他 tab 为 read-only mirror：可展示 plugin 已保存快照；发送请求进入该 tab UI 队列并等待 ownership，不能本地追加消息或保存。
- writer 无 active turn 且保存队列已 drain 后才能 release；ownership FIFO 转交。
- close/destroy/switch 必须 release；plugin unload 统一 drain/cancel。
- 锁位于 plugin 实例而非单个 TabManager/view，覆盖多个 Claudian view。

不做分叉合并；单写者从源头禁止基于同一旧快照产生两个写分支。

#### 6.2 完整保存快照

`ConversationController` 构建不可变 `ConversationSaveSnapshot`：

| 字段 | 来源/merge 规则 |
|---|---|
| `conversationId`, `writerTabId`, `turnId`, `baseUpdatedAt` | 捕获时固定；落盘前验证 writer ownership。 |
| `messages` | writer tab 的完整深拷贝；同一 turnId 只提交一次。 |
| `usage` | 本 turn 最终 usage；无新 usage 时保留 storage 当前值，不写 `undefined` 清空。 |
| `sessionId`, `providerState` | `runtime.buildSessionUpdates()` 的快照结果；与 messages 同次提交。 |
| `sessionInvalidationEpoch` | runtime 单调 epoch；若大于 conversation 已保存 epoch，则本次 `sessionId=null`。成功落盘后 ack 该 epoch。禁止 save 前 consume。 |
| `currentNote` | writer 当前 FileContext；未设置时按现有语义写 `undefined`。 |
| `externalContextPaths` | writer 当前 selector 全量；空数组按现有持久化语义转 `undefined`。 |
| `enabledMcpServers` | writer 当前 selector 全量；空数组转 `undefined`。 |
| `resumeAtMessageId` | 默认保留 storage 当前值；rewind 显式 replace；正常成功发送按现有 `saveExtras` 显式 clear。 |
| `lastResponseAt` | 仅 turn 成功完成/auto 投影完成时设当前时间；普通 lifecycle save 保留。 |
| `title/titleGenerationStatus` | 不由通用 save 快照改写，继续走专用 update 路径；单写锁不阻塞标题元数据更新。 |

保存实现仍放在 `ConversationController.saveSnapshot()`；plugin writer entry 的 `queue` 串行执行。每次执行前重新读取 storage conversation，并按上表 merge，避免 `undefined` 意外清字段。

#### 6.3 session invalidation 原子事件

替换 `ChatRuntime.consumeSessionInvalidation()`：

```typescript
getSessionInvalidationEpoch(): number;
ackSessionInvalidation(epoch: number): void;
```

`SessionManager.invalidateSession()` 递增 epoch；snapshot 捕获 epoch。只有包含该 epoch 的 save 成功后 ack；合并/丢弃的旧 save 不消费事件。若更高 epoch 已产生，ack 低 epoch 不清高 epoch。

#### 6.4 save call-site 迁移表

| 调用点 | 新行为 |
|---|---|
| `InputController` 用户轮 finally `save(true, saveExtras)` | writer 锁内构建 turn snapshot；await state save，含 lastResponseAt 与 resume clear。 |
| auto notification/Stop 续轮完成 | 与回喂成对上线；构建 auto turn snapshot，最多有界等待，含 messages/usage/session update/lastResponseAt。 |
| `SubagentManager.onStateChange` 的 background save | 若无 active projection，只 enqueue 最新 snapshot；不得直接 `save(false)`；同一 terminal turn 合并。 |
| `ConversationController.switchTo()` 前 | 当前 writer enqueue lifecycle snapshot 并 drain；完成后 release ownership，再 restore 新 conversation。 |
| `ConversationController.createNew()` 前 | 同上；force 时先 cancel all turns，再保存取消后的最终快照。 |
| `ConversationController.rewind()` | writer 独占；truncate 后 snapshot 显式 replace `resumeAtMessageId`，保存成功才报告 rewind 完成。 |
| `TabManager.closeTab()` | 非 force：drain writer queue后 release；force：cancel turns，提交可用最终 snapshot并设置有界等待。 |
| `TabManager.destroy()` / plugin unload | 按 conversation 去重，只由 writer 保存一次；禁止现有“所有 tab 并行 save”。 |
| provider/session invalidation | 不直接 save；epoch 随下一 snapshot 原子落盘；需要立即持久化时 enqueue lifecycle snapshot。 |
| 标题生成专用 `updateConversation` | 只改 title/status，不参与消息快照；执行时读取最新 conversation 后 patch。 |

### 7. 有界完成协议

不新增独立 SaveQueue 组件；复用 plugin `conversationWriters[conversationId].queue`。

- state projection 必须 await，最大 5s watchdog。
- snapshot save 排入 conversation writer queue；auto/user turn最多 await 3s。
- 超时只释放 turn，不取消已排队 save；queue 后续仍按顺序收敛。写前校验 owner 与 snapshot turnId；若 ownership 已转移，旧 owner snapshot 丢弃并告警。
- save reject 保持 queue 可继续，下一 snapshot基于 storage 最新值重试；不回滚内存状态。
- projection cancel/超时：不生成 snapshot；阶段 1终态销账不回滚。

完成顺序：

```text
result → projection（≤5s）→ snapshot enqueue/await（≤3s）
→ finish feature lease → settle RuntimeTurn → MessageChannel.completeTurn(turnId)
→ 执行 deferred config restart → 转发下一 queued user turn
```

### 8. 分步落地

1. **S1：MessageChannel + RuntimeTurn + cancel。** user dequeue、external auto、canonical waiters、turn-scoped transform、强制结算；旧 auto renderer暂保留。可独立验证/回滚。
2. **S2：feature 仲裁 + lifecycle generation。** InputController 内排他 lease，auto start 同步占位，switch/new/destroy cancel；旧 auto renderer仍消费结果。可独立验证/回滚。
3. **S3：domain/DOM 解耦。** SubagentManager 与 StreamController 改 domain-first；用户轮保持行为等价。可独立上线。
4. **S4+S5：全量 auto 回喂 + 单写者保存一次上线。** 删除旧 renderer，接 usage、空消息、plugin writer lock、完整 snapshot、invalidation epoch、有界完成协议。不可拆分。
5. **S6：全量回归、构建与运行时 V5。**

## 风险与权衡

- 单写者意味着同 conversation 多 tab 不再允许并行编辑；这是避免无合并语义快照覆盖的明确产品约束。
- collecting turn 的配置变更延迟到 settled；本轮继续使用旧配置，下一轮生效。比跨 Query 伪续流可靠。
- projection watchdog 触发时 UI 可能缺该 auto turn；通知权威终态已独立完成，reload 可由 transcript 恢复。
- S4+S5 改动耦合高，必须同一实现批次、同一复核批次上线。

迁移代价：需调整 provider runtime、MessageChannel、InputController、StreamController、SubagentManager、ConversationController、TabManager 与 plugin persistence；不新增 registry/coordinator/save service 文件，控制结构数量。

## 验证方式

### 二轮复核十项

1. **auto 首 chunk 前发送**：通知依次触发 `beginExternalTurn → onAutoTurnStarted → dispatch`；用户仅排 UI 队列。未 dequeue handler 不夺 lease。
2. **reset/restart**：active turn 时 config restart 延迟；session switch 强制 cancel；不存在跨 Query 保留 chunk 的断言。
3. **flush 排他**：auto 期间 `isStreaming=true`、`currentContentEl` 只属 auto；finish 后用户轮才建 DOM/handler。
4. **stale callback**：projection 每个 await 后切会话/关 tab/restart，旧 callback不写 state/usage/save。
5. **永不 settle**：fake timer 到 5s，cancel turn、所有 waiter 退出、channel 放行。
6. **detached DOM 四案**：真实调用 Task/thinking/notice/error；Task 完整转态，后三者写 ChatMessage，renderer 零调用。
7. **连续/空 auto**：两个 turn 的 metadata/usage/dedup 隔离；空轮无 bubble且正确 complete external turn。
8. **Stop 续轮再派 Task**：domain record建立，usage 仅按该 turn spawn 口径，通知销账一次。
9. **后台 tab**：RAF 收敛、writer save、meter/badge更新；切回不重复 render。
10. **多 tab 同 conversation**：只有 writer 可 send/save；另一 tab排队；ownership 转交后从最新 storage 恢复再写，无分叉覆盖。

### 必补契约测试

- `MessageChannel.beginExternalTurn/completeTurn` 与 user dequeue互斥、错误 turnId fail-fast。
- `cancelQueuedTurn/cancelAllTurns` 令每个 handler generator done/error，包括 canonical merged waiters。
- notification 顺序 spy：feature start 严格早于 notification handler，notification handler早于任何 transform。
- invalidation epoch：被合并/丢弃 save 不 ack；成功保存 epoch N 不清 N+1。
- 全字段 snapshot merge：messages、usage、session/provider state、note、external paths、MCP、resume、lastResponseAt逐项覆盖。
- destroy：同 conversation 多 tab仅保存一次，不再 Promise.all 全 tab并写。
