## 2. S4 投影新时序——echo 租约绑定

### 2.1 核心机制

**用户轮租约的激活点从"消息 enqueue"改为"SDK 回显该消息"**：

- 用户消息进 MessageChannel 时携带 UUID（`buildSDKUserMessage` 已赋 uuid，ClaudeChatRuntime.ts:2080）
- runtime 的 routeMessage 观察到 user echo（`type==='user'` 且非 tool_result 回传、UUID 匹配 pending 消息）才将对应 RuntimeTurn 置为 active 并签 channel lease；消息在 channel 队列中尚未被 SDK echo 的期间，任何 SDK 首条 assistant/stream 消息归 auto turn（ensureAutoTurn 现有逻辑）
- 归属由**事件因果**裁决：SDK 先 echo 用户消息 → 后续 assistant 归用户轮；续轮首消息先到 → 归 auto turn。无需时间窗、无需启发式屏障、无需通知预占
- 现有 `handleTurnDequeued`（ClaudeChatRuntime.ts:1314）的 dequeue 签 lease 改为 echo 签 lease；channel queue 语义不变（仍按序投递），仅 activeTurnId 的签发点后移

### 2.2 S-0 前置探针（实施第一步，结论不成立则本节重估）

探针脚本模式沿用 /tmp/stop-hook-probe.mjs（工程目录内 node 跑，代理路由）：向 prompt iterable yield 带 uuid 的 SDKUserMessage，观察 SDK 是否在响应流中原样回显该 uuid（user echo 消息）。若不回显，echo 绑定不成立 → 退化为"接受通知后窄窗口串线 + S5 治理"（串线后果：续轮内容并入用户轮投影，无正确性损失仅归属观感偏差），并记录于本文档修订。

### 2.3 投影流程（auto turn）

- 纯通知：只销账（c5ad19d 现行为）
- 续轮：首消息到达建 auto turn（ensureAutoTurn）→ chunks 走 TurnProjectionContext 复用（StreamController.ts:85/98 已就绪）→ 事务化提交（§4）→ 空消息收口（纯 usage/纯隐藏 TaskOutput 无可见内容不生成消息，usage/subagent 状态照常提交）

## 3. S5 ConversationCoordinator 单写者

新建 `src/features/chat/services/ConversationCoordinator.ts`，plugin 单例（main.ts 装配，覆盖多 view），从 61f7692 的 main.ts 内联实现（L884-1003 一带）选择性参考重写。

### 3.1 状态机

`unowned | granting | owned | releasing`；owner token `{tabId, epoch}`；请求去重（同 tab 重复 requestOwnership 返回同一 Promise）。

### 3.2 原子新建（堵 S5 审查实证的首轮保存丢弃洞）

新会话"createConversation + 注册 ownership"为单原子操作（对齐 main.ts:594 createConversation 与 ownership 注册的时序）——conversation 创建即有 owner，首 turn 的 snapshot 携带 writerTabId 时 ownership 表必然已有对应条目，executeSaveSnapshot 的 owner 校验不再丢弃首轮。

### 3.3 grant 管线与保存队列

- grant：撤销旧 runtime → durable barrier（saveTail drain）→ 加载最新 storage → hydrate mirror → 激活唯一 runtime → commit owned；失败回滚流转下一等待者；等待中 tab 关闭移除 FIFO 项（61f7692 已有实现可复用：removeConversationOwnershipWaiter/grantNextWaiter 流转）
- 保存：串行命令队列（SaveOperation：revision / ownerEpoch / durability(normal|final) / 字段 intents）；语义操作不合并；commit 对最新 storage 执行，返回 written | superseded | rejected | failed
- final commit：coordinator 持不可变快照，release 等待 final 落盘；UI 可先关（tab detach），coordinator 以 headless ownership 保留至落盘
- 存储事实（实施时按此对接）：SessionStorage.saveMetadata 为整文件全量 JSON 快照（SessionStorage.ts:27-32）；VaultFileAdapter 的 writeQueue 仅 append 串行，write 不串行——保存队列的串行性由 coordinator 自持，不依赖 adapter

### 3.4 明确限制与已知观察项

- **硬进程退出无法保证**（无同步存储可用）：final 落盘窗口内强杀进程会丢最后一次保存。列为已知限制，不引入 WAL（无证据值得此复杂度）
- mirror 竞态收通知只 drain/销账 no-op 投影（61f7692 §4.6 实现可复用）

## 4. 投影事务化提交

- **AutoTurnProjectionDraft**：assistant message + usage delta/final + subagent 变更的隔离草稿；chunks 以 renderTarget=null 回放（S3 domain-first 已支持无 DOM 路径）
- 一次性 commit：ownership token + lifecycle generation + lease 三校验通过才写入真实 state/managers；渲染在 commit 后进行且可取消——渲染失败/取消不影响轮次正确性
- 取代 5s watchdog 弃轮：AbortSignal 真取消（0133ab7 invalidateRenderFlush 已就绪）；超时只触发 abort 再 await 退出，**不允许弃轮**
- **完成握手**：InputController 在 finalize+save 后显式 `acknowledgeTurnProjection(turnId)`；runtime 持有至 ack 才 completeTurn 释放 channel——两层完成顺序由握手保证而非顺序约定（替代 v4 §3.1 的七步顺序约定）。取消/异常路径在 finally 中 ack（abort 形态）确保不悬挂
- 空可见内容轮：不 append 消息，仍 commit usage/subagent 并保存
