# Claudian 阶段 2 S4 重设计 v3

> 路径：[理想]。源码基线固定为 `hotfix/notify-lease@99dca6b`；`bbb431f` 的 finalize 渲染可取消保护已包含在该基线。本文替代 [[2026-08-23-Claudian阶段2-S4S5重设计-v2]]。
>
> 范围结论：只设计 S4；S5 整体砍除。实施不得 cherry-pick `61f7692`，只能按本文重新实现 S4。

## 背景与问题

当前 `MessageChannel.activeTurnId` 同时表达“某条用户消息已经 dequeue、不得继续投递”和“入站 SDK 消息应归属于哪个 turn”。这两个事实并不同时成立：用户消息 dequeue 后，在 SDK 原样 echo 其 UUID 之前，空闲期续轮仍可能先到。单字段模型因此无法同时保证队列背压与正确归因。S4 要以两层状态机、隔离投影和可等待 ack 消除该歧义；S5 的多窗口 conversation 单写者治理因场景不存在而移出范围。

## 方案设计

### 1. v2 → v3 变更点

| v2 | v3 | 原因 |
|---|---|---|
| `activeTurnId` 在 dequeue 时直接成为用户轮租约 | 拆为 delivery reservation 与 attributed turn lease | dequeue 只证明消息在途，不证明后续 SDK 消息已归属该用户轮 |
| echo UUID 单探针，失败可接受窄窗口串线 | S-0 八场景探针；任一失败即停止实施 | 串线会污染 usage、todos、plan、subagent 等共享状态，不能视为无正确性损失 |
| pending text 重建仅保存文本 | pending envelope 保留 canonical UUID；文本合并和附件替换均不得换 UUID | `pendingToMessage` 当前会丢 text UUID，附件替换当前会把 canonical turnId 与新消息 UUID 拼错 |
| routeMessage 五道门，白名单在前 | 六道门：lease → result → control → notification → echo → auto 白名单 → ensureAutoTurn | echo 必须先于 auto 白名单识别，否则合法 user echo 会被当作非轮次消息丢弃 |
| `TurnProjectionContext(renderTarget=null)` 视作事务草稿 | 新增独立 `AutoTurnProjectionDraft` reducer/adapter；回放禁止触碰真实共享状态 | 现有 StreamController 仍直写 usage、todos、planFilePath、SubagentManager maps，并非隔离 |
| callback 同步触发后 runtime 继续 release | callback 改为 Promise ack；runtime await 后才完成 attributed lease | 投影、保存未完成前不能 dequeue 下一用户消息 |
| 取消/异常 finally 仅概念性 ack | 明确单次 settling promise + 幂等 ack；所有终态共用 | 防止重复 complete、异常悬挂或绕过 pump |
| crash replay 只按 turnId 重 enqueue | replay 前重建 UUID→turn pending 索引和 reservation | 重启后仍须用同一消息 UUID 完成 echo 绑定 |
| 新增裸 `console.debug` | 使用可移除诊断适配器；S4' 后清除现有 14 个诊断调用点 | 仓库禁止生产代码 `console.*` |
| S5：ConversationCoordinator、ownership/grant、单写者、final commit | **整体砍除** | 用户确认 Claudian 不支持两窗口打开同一会话，也无该业务场景 |
| 保存并入 S5 coordinator | 维持 `saveTurnSnapshot` / `enqueueAutoTurnSave` 现有基线语义，不加 ownership、epoch、final commit | S4 只要求 auto 投影完成后按现有方式保存 |
| S1'—S5' | S-0 → S1' → S2' → S3'；S4' 仅作总验收与诊断清除 | 删除全部 S5 实施内容 |

### 2. 两层状态机

#### 2.1 状态字段

改造 `/Users/vincentwang/Documents/NoteVault/tools/claudian/src/providers/claude/runtime/ClaudeMessageChannel.ts`，删除语义混合的 `activeTurnId`，引入两个正交状态：

```ts
type DeliveryReservation = {
  canonicalTurnId: string;
  messageUuid: string;
  phase: 'awaiting-echo' | 'echo-observed';
};

type AttributedTurnLease = {
  turnId: string;
  kind: 'user' | 'auto';
  generation: number;
};
```

- `deliveryReservation`：消息从 queue 交给 SDK iterable 时建立；唯一职责是保持“单条用户消息在途”，阻止下一条用户消息 dequeue。
- `attributedTurnLease`：入站消息的归属；只在合法 user echo 命中 reservation，或白名单允许的 auto 首消息到达后建立。
- 两者可以同时存在且 owner 不同：auto-first 时，用户消息 reservation 在等待 echo，auto lease 临时归属空闲期续轮。
- `isTurnActive()` 拆为明确查询：`hasDeliveryReservation()`、`getAttributedTurnLease()`、`isChannelOccupied()`。队列投递只看 reservation；routeMessage 只看 attributed lease。

`RuntimeTurn.phase` 相应细化：用户 turn dequeue 后仍保持 `reserved`（新增 phase），echo 绑定后才进入 `collecting`；auto turn 直接从创建进入 `collecting`。不得再由 dequeue hook 把用户 turn 置为 collecting。

#### 2.2 pending 数据结构与 UUID 不变量

改造 `/Users/vincentwang/Documents/NoteVault/tools/claudian/src/providers/claude/runtime/types.ts`：

```ts
type PendingMessage = {
  kind: 'text' | 'attachment';
  canonicalTurnId: string;
  canonicalUuid: string;
  message: SDKUserMessage;
  joinedTurnIds: string[];
};
```

硬不变量：

1. `message.uuid === canonicalUuid`，从 enqueue、排队、合并、替换、dequeue、crash replay 到 SDK echo 全链不变。
2. `canonicalTurnId` 始终是队列项首个 turn；后续合并 turn 只加入 `joinedTurnIds` 并复用 canonical turn 的 waiters/settlement。
3. 文本合并：复制首条 `message` envelope，仅替换 `message.message.content`；不得由 `pendingToMessage` 新建无 UUID 对象。
4. 附件替换：保留首条 `canonicalTurnId`、`canonicalUuid` 及 envelope 身份字段，只用新消息的 content 替换 payload；不得直接保存带新 UUID 的整条 message。
5. `pendingToMessage` 退化为返回已规范化的 `pending.message` 副本，并断言 UUID 与 canonicalUuid 一致；不再从裸 `content` 重建 SDKUserMessage。
6. UUID 缺失视为协议错误：enqueue fail-fast、settle 对应 turn，不允许生成替代 UUID 后继续。

#### 2.3 三个 dequeue 挂点

当前三个挂点位于 `ClaudeMessageChannel.ts:139-147`、`:254-260`、`:270-280`。统一收敛到私有原子操作 `reserveAndDeliver(pending, resolve?)`：

1. 断言 `deliveryReservation === null`。
2. 建立 `{canonicalTurnId, canonicalUuid, phase:'awaiting-echo'}`。
3. 调用改名后的 `onTurnReserved(canonicalTurnId, canonicalUuid)`。
4. 最后向 iterator 返回/resolve `pending.message`。

三处不得各自复制状态迁移。回调先于消息可见，避免 SDK 同步回显时 runtime 索引尚未建立。原 `handleTurnDequeued` 在 `/Users/vincentwang/Documents/NoteVault/tools/claudian/src/providers/claude/runtime/ClaudeChatRuntime.ts:1342-1361` 改为 `handleTurnReserved(turnId, uuid)`：

- runtime turn 不存在：释放该 reservation，并通知 feature `cancelTurnFromRuntime`；
- turn 存在：phase 置为 `reserved`，登记 `pendingEchoes.set(uuid, {turnId, generation})`；
- 不建立 attributed lease。

#### 2.4 auto-first 与 echo-first 竞态

竞态仅按 `routeMessage` 单线程消费顺序裁决，不设时间窗：

- **echo-first**：合法 user echo 先到且无 attributed lease → 将 reservation 原子绑定为 user lease，phase `collecting`；后续 assistant/stream_event 归用户 turn。
- **auto-first**：assistant/stream_event 先到且无 attributed lease → 建 auto turn/lease；reservation 保留。若 user echo 随后到达，只把 reservation 标为 `echo-observed`，不得抢占 auto lease，也不得把 auto 已收 chunks 改归用户。
- auto turn ack 完成后，若 reservation 为 `echo-observed`，在释放 auto lease与处理下一条 SDK 消息之间同步 promote 为 user lease；若仍 `awaiting-echo`，只释放 auto lease并继续等 echo。
- 同一 UUID 重复 echo：已绑定同一 user lease时幂等忽略；lease/reservation 不匹配时作为协议错误记录并停止该 query，不做启发式归属。

#### 2.5 channel 完成语义

把旧 `completeTurn(turnId)` 拆为两个明确操作：

- `releaseAttributedLease(turnId, generation)`：仅释放匹配的归属租约；auto turn 只调用它，不碰用户 reservation。
- `completeReservedDelivery(turnId, uuid)`：仅在对应用户 turn 达到终态（result 已处理且 feature 完成，或取消/错误已 settle）时，同时释放 user lease、pendingEcho 索引和 reservation，然后由 `deliverNextIfWaiting()` 投递下一项。

规则：

- user result：ack/用户轮既有 finalize 完成后 `completeReservedDelivery`。
- auto result：ack 后 `releaseAttributedLease`，再执行上述 deferred promotion；reservation 不释放。
- user cancel/error：幂等清除其 lease + reservation + pending echo，才允许下一项 dequeue。
- auto cancel/error：幂等清除 auto lease；保留 reservation并按 echo 状态 promote/等待。
- close/reset/cancelAll：返回 reservation owner、lease owner与 queued owners 的去重集合；runtime 逐 turn settle。不得因 owner 重合重复回调。

任何释放都不得直接触发 feature 队列 pump。唯一 pump 仍是 `/Users/vincentwang/Documents/NoteVault/tools/claudian/src/features/chat/controllers/TurnCoordinator.ts` 的 `release` 路径。

### 3. 六道门与 echo 绑定

改造 `/Users/vincentwang/Documents/NoteVault/tools/claudian/src/providers/claude/runtime/ClaudeChatRuntime.ts:962-1024`。routeMessage 固定顺序：

1. **active lease 解析**：仅从 `attributedTurnLease` 找 RuntimeTurn；reservation 不作为归属。
2. **trailing result**：无 lease 的 result 继续丢弃，禁止创建 ghost turn。
3. **system control**：无 lease 的 leaseless system control 只做 session side effect。
4. **task notification**：无 lease的纯通知只销账；有 lease时沿现有 turn 内通知分支处理。
5. **pending user echo 匹配绑定**：尝试精确绑定 reservation。
6. **auto 白名单**：仍仅允许 `assistant | stream_event` 开 auto turn；其余无 lease消息丢弃。通过后才 `ensureAutoTurn()`。

其中“六道门”将第 6 项视为“白名单判定 → ensureAutoTurn”的同一道 auto-start 门；不得把 ensureAutoTurn 前移。

#### 3.1 echo 接受条件

四项必须同时满足：

- `message.type === 'user'`；
- message content 不是 tool_result 形态：content 数组中不存在 `type:'tool_result'`，且不是 provider 的 user-tool-result envelope；
- `message.uuid` 为非空字符串；
- UUID 精确命中 `pendingEchoes`，且命中项与当前 `deliveryReservation.{canonicalTurnId,messageUuid}` 一致。

合法 echo 是归因控制消息，不进入 `transformSDKMessage`，避免把用户文本投影成 assistant 内容。`type=user` 的 tool_result 必须继续走已归属 turn 的 transform；无 active lease 时不得误绑 reservation，也不得开 auto turn。

#### 3.2 runtime 索引

在 `ClaudeChatRuntime` 增加：

```ts
pendingEchoes: Map<string, { turnId: string; generation: number }>;
```

只由四条路径修改：reservation 建立、echo 成功/观察、用户终态清除、crash replay 重建。禁止通过“最近发送 turn”或文本相等回退匹配。

#### 4.4 commit

commit 前一次性校验：

1. TurnCoordinator 仍持有同一 `{turnId,generation}` auto lease；
2. 当前 conversationId 等于 `baseConversationId`；
3. runtime 未 cancel，draft 已 finalized；
4. 同一 `{turnId,generation}` 尚未 committed/aborted。

校验失败：整份 draft 丢弃，返回 acknowledged-aborted，不得部分写入。校验通过：在不含 `await` 的同步临界段依次应用 messages、usage、todos、plan、subagent patch，并记录 committed token；之后才做 DOM 渲染与保存。JS 单线程下该同步段即原子可见边界。

空可见内容轮：不追加 assistant message，但 usage/todos/plan/subagent patch 仍可 commit 和保存。

#### 4.5 与 `bbb431f` 的分工

- draft 解决 **auto 回放的数据隔离与原子提交**。
- `bbb431f` 的 `awaitRenderCancelable` 继续保护 **用户轮 live finalize**，以及 **auto commit 后的 DOM 渲染**。
- 渲染永远在 commit 后；取消/切 tab 可跳过或中断渲染，但不能回滚已提交 domain data，也不能阻塞 ack。
- 不允许以 render promise 成功作为数据 commit 条件。

### 5. 可等待 ack 协议

#### 5.1 契约

首选直接升级 provider-neutral 接口：

```ts
setAutoTurnCallback(
  callback: ((result: AutoTurnResult) => Promise<void>) | null
): void;
```

并扩充 `AutoTurnResult`：

```ts
interface AutoTurnResult {
  turnId: string;
  generation: number;
  chunks: StreamChunk[];
  metadata: ChatTurnMetadata;
}
```

需同步修改：

- `/Users/vincentwang/Documents/NoteVault/tools/claudian/src/core/runtime/ChatRuntime.ts:58`
- Claude runtime callback 字段与 `setAutoTurnCallback`；
- Codex、Opencode 的实现签名（仍可 no-op）；
- `/Users/vincentwang/Documents/NoteVault/tools/claudian/src/features/chat/tabs/Tab.ts:1723-1731` wiring。

不选独立 `acknowledgeTurnProjection(turnId)`：它把“谁完成投影”和“谁发 ack”拆成两个调用，容易漏 ack；Promise callback 将 ack 与唯一投影调用绑定。

#### 5.2 runtime 等待顺序

`settleTurnAtResult` 的 auto 分支改为：

1. turn phase → `projecting`，冻结 chunks/metadata；
2. 创建/复用该 turn 的 `projectionAckPromise`；
3. `await _autoTurnCallback(result)`；无 callback 视为 acknowledged-aborted并记录诊断；
4. feature 内部顺序：建 draft → reducer 回放/finalize → commit 或 abort → commit 后可取消渲染 → `saveTurnSnapshot` / `enqueueAutoTurnSave` 沿现有基线语义完成；
5. Promise settle 后才 `finish` feature lease、执行 deferred restart、runtime settle；
6. auto：`releaseAttributedLease`，再触发 `onAutoTurnReleased`；user reservation 不受影响。

保存保持当前单 tab 语义，不增加 ownership/grant/final commit。若基线函数尚未从历史实现回移，S3' 只恢复无 ownership 校验的 `saveTurnSnapshot` / `enqueueAutoTurnSave` 等价路径；不得带入 `61f7692` 的 ConversationCoordinator 或 writer token。

#### 5.3 异常、取消与幂等

每个 auto turn 维护唯一终态：`pending | committed | aborted` 与唯一 `projectionAckPromise`。

- reducer/commit/save 抛错：feature 捕获，标记 aborted 或 committed-with-save-error，用户可见 Notice，最终 resolve ack；不得 reject 到 consumer loop导致 channel 悬挂。
- runtime cancel、tab switch、conversation switch：触发 draft AbortSignal；未 commit 则丢弃，已 commit 则只取消 render；最终 resolve 同一个 ack。
- callback 重入、重复 result、重复 cancel：返回同一个 Promise；commit token 防二次写，channel release 校验 generation 防二次释放。
- runtime cleanup 若 callback 永不返回：cleanup 主动 abort feature scope并等待其 finally resolve；不加超时弃轮。
- 所有路径最终都通过 `TurnCoordinator.finish` → runtime channel completion → `onAutoTurnReleased` → `TurnCoordinator.release`；禁止 callback、Tab 或 StreamController 直接调用 queue pump。

### 6. crash replay 适配

当前 replay 位于 `/Users/vincentwang/Documents/NoteVault/tools/claudian/src/providers/claude/runtime/ClaudeChatRuntime.ts:856-884`。在 `messageChannel.enqueue(replayTurnId, messageToReplay)` 前必须：

1. 从 `messageToReplay.uuid` 取 UUID；缺失则停止 replay并 settle error。
2. 清理旧 query 的 stale attributed lease / reservation，但保留 RuntimeTurn 与 handler。
3. `reRegisterTurnForRetry` 后，以同一 `{turnId, generation, uuid}` 重建 pending echo 关联。
4. enqueue 原消息 envelope，不重建 UUID。
5. 若 consumer 正在等待，enqueue 同步建立 reservation；若先排队，则在 dequeue hook 建 reservation与 pendingEcho。
6. replay 只允许一份 reservation；旧 query 的迟到 echo/result因 query identity/generation 不匹配而丢弃。

replay 测试必须证明：重启前后 turnId、UUID、handler、最终 user lease均为同一逻辑 turn，且不会额外创建 auto turn。

### 7. S-0 探针矩阵

探针使用真实 SDK persistent query；脚本放工程 `.context/`，不进入生产代码。每项都记录原始消息序列、type/subtype/uuid/content shape 与断言。**任一断言不成立：停止 S1'—S3' 实施，不提供降级路线。**

| # | 场景 | 操作 | 必须成立的断言 |
|---|---|---|---|
| 1 | 等待中直投 | consumer 已 await `next()` 时发送带 UUID 文本 | 返回流出现非 tool_result user echo；echo UUID 与发送 UUID 完全相同；echo 位于该用户响应 assistant/stream 前 |
| 2 | 排队后重建 | 先占用一轮，再排队文本，待前轮结束由 `pendingToMessage` 交付 | dequeue 后 echo UUID 仍等于原 UUID；不得缺失或新生 UUID |
| 3 | 两文本合并 | active 期间连续排入两条文本 | SDK 只收到一个合并 envelope；UUID 为首条 canonical UUID；内容顺序为 `first\n\nsecond`；第二 turn 明确 alias 到 canonical turn |
| 4 | 附件排队替换 | active 期间排附件 A，再以 B 替换 | 最终 payload 为 B；UUID/turnId 仍为 A 的 canonical pair；不得出现 A turnId+B UUID |
| 5 | crash replay | 用户消息 dequeue 后、任何 chunk 前制造 consumer error并 replay | replay 使用原 UUID与原 turnId；只产生一个合法 echo 绑定和一个最终结果；无 ghost auto turn |
| 6 | user tool_result 区分 | 制造 SDK `type=user` 且 content 含 tool_result | 不命中 pending user echo；在已有 lease下按 tool_result 处理；无 lease时不得开 auto turn |
| 7 | echo / stream_event / assistant 先后 | 分别捕获正常用户轮与通知续轮的真实顺序，至少覆盖 echo-first、auto-first | echo-first 绑定 user；auto-first 建 auto；assistant 完整消息与 stream_event 无论谁先都不改变已裁决 owner；不得靠时间窗 |
| 8 | 各形态 UUID 保持性 | 文本、图片、文本+图片、合并文本、附件替换、crash replay逐一取证 | 每个实际交付 envelope 均有 UUID；echo UUID精确等于其 canonical UUID；全链无 UUID 丢失/替换 |

S-0 除真实探针外，先补 MessageChannel 纯单测作为仪器自校验；mock 结果不能替代真实 SDK 结论。

### 8. 分步实施与验收门

#### 8.1 实施顺序

#### 8.2 单元/集成验收

- MessageChannel：三挂点共用原子 helper；reservation 背压；auto lease 与 reservation 并存；合并/替换 canonical UUID；双重完成幂等；close/reset owner 去重。
- routeMessage：六道门顺序逐项锁定；user echo 与 user tool_result 分离；auto-first/echo-first；result 尾随非轮次消息不建 auto。
- draft：每种 chunk 两种结果——draft 正确、真实 ChatState/SubagentManager 未变；commit 后四类状态一次性一致。
- ack：延迟 callback Promise 时下一 queued turn 不 dequeue；resolve 后仅 `TurnCoordinator.release` 触发 pump；reject/cancel/duplicate result 不悬挂、不二次 commit。
- replay：旧 query 迟到消息、同 UUID replay、generation mismatch、handler 保留。
- provider 兼容：Codex/Opencode 类型检查与原行为不回归；S4 行为只在支持 SDK auto turn 的 Claude runtime 生效。
- 基线测试：`npm run typecheck && npm run lint && npm run test && npm run build` 全通过；测试数量以实施时 `99dca6b` 实际基线为准，不沿用 v2 的 5565 硬编码。

#### 8.3 运行时事故家族冒烟

每项同时检查 UI、诊断事件、conversation state、channel reservation/lease、TurnCoordinator phase 与保存结果：

1. **result 毫秒级尾随消息**：result 后紧跟 queue-operation/未知 bookkeeping；不得建 ghost auto、不得卡 running。
2. **纯通知**：只销账，无 auto turn、无 assistant message、无 lease。
3. **通知 + 续轮**：通知销账；assistant/stream 首消息建 auto；draft 全量 commit并保存。
4. **通知后立即发送**：覆盖 auto-first 与 echo-first；内容、usage、todos、plan、subagent均归正确 turn。
5. **长 Markdown/数学渲染期间取消并切 tab**：domain commit/abort符合时点；render 可取消；ack必达；旧 tab无迟到 DOM 写。
6. **连续多轮**：每轮 UUID、reservation、user lease成对建立/释放，无残留。
7. **排队多轮**：严格单消息 reservation；文本合并/附件替换行为与 UUID 不变量一致；无饥饿。
8. **crash replay**：同 turn/UUID成功恢复；旧 query 迟到消息不污染新 generation。
9. **后台任务空闲期完成全链**：notification → auto start → draft replay → atomic commit → render/save → ack → finish/release → queued user pump，顺序完整且各节点仅一次。

任一冒烟失败均阻断部署和诊断清除。

### 9. 埋点与清除清单

#### 9.1 新增诊断规范

新增 `TurnDiagnostics` 之类的单一设施，底层使用项目 logger 的 debug sink，或通过构建常量在 production tree-shake；生产业务文件禁止直接 `console.debug`。事件采用结构化字段：

- `event`：`reservation.created|echo.observed|lease.bound|draft.committed|projection.acked|lease.released` 等；
- `turnId`、`generation`、`kind`；
- `uuid` 仅记录短 hash/后 8 位，不记录消息正文；
- `reservationOwner`、`leaseOwner`、`reason`、`queryGeneration`；
- 每个状态迁移一个事件，禁止在 chunk 热路径逐 token 打印。

S4' 通过后删除临时调用；若保留设施，仅允许默认关闭且生产构建可剥离的通用 logger，不保留事故专用埋点。

#### 9.2 现有诊断清除

`99dca6b` 实证有 14 个事故诊断调用点（不是 14 行输出）：

- `StreamController.ts`：12 个 `console.debug` 调用点——finalize text 2、text flush 4、finalize thinking 2、thinking flush 4；
- `TurnCoordinator.ts`：1 个 `traceLease` 内的 `console.debug` 调用点；
- `ClaudeChatRuntime.ts`：`runtime.result`、`generator.finally` 与 deferred restart begin/end 共 5 个调用点。

因此仓库当前实际是 **18 个 `console.debug` 调用点**；“14 处”是按诊断主题/旧审查口径，不应作为机械 grep 期望值。S4' 清除清单以 `rg -n "console\\.debug" src` 为准，目标为 0，并同步删除只服务于事故取证的 wrapper/comment。`console.warn` 是否迁移不属于本次清单，但不得新增裸 console。

### 10. S5 砍除记录

S5 整体移出当前及后续实施序列：不创建 `ConversationCoordinator`，不设计 ownership/grant/waiter FIFO，不引入 conversation 单写者、owner epoch、durable barrier 或 final commit。理由是用户确认不存在多窗口打开同一会话场景，且 Claudian 本身不支持该操作。

`61f7692` 的“首轮保存丢失”由其新增 ownership 校验与 conversation 注册时序不一致所制造；`99dca6b` 没有该校验，砍除 S5 不会移除现有保护。保存维持单 tab 当前语义：用户轮 `saveTurnSnapshot`，auto 轮 `enqueueAutoTurnSave`；本设计只要求 ack 等待这条既有保存链完成，不改变一致性模型。

## 风险与权衡

1. **最大前提是 SDK echo 契约**：S-0 任何形态不保 UUID，方案即失去因果锚点，必须停止而非降级猜测。
2. **auto-first 中 echo 延迟 promotion**：短期同时存在 auto lease 与 user reservation，状态比单 lease复杂；换来严格背压与因果归因，且由单线程 routeMessage 保证确定性。
3. **draft adapter 改造面较大**：必须覆盖四类共享写点，不能只隔离 assistant message；这是防止取消/切 tab污染真实状态的必要代价。
4. **ack 无超时逃生**：错误实现会暴露为挂起，但超时释放会重新引入并发投影。设计选择 fail-fast诊断和可取消 finally，不接受超时越权释放。
5. **保存契约的基线差异**：`99dca6b` 当前源码仍可见用户轮直接 `ConversationController.save(...)`，而 `saveTurnSnapshot` / `enqueueAutoTurnSave` 名称来自被回滚实现。实施时只能恢复其“不可变快照 + tab 内 auto save 串行”语义，不得恢复 ownership 校验；该点需在 S3' diff 审查中单列。
6. **无多窗口一致性保证**：这是明确范围边界，不是遗漏。若未来产品支持同 conversation 多 view，须另立新设计，不能在 S4 上补 owner if 分支。

### 迁移/落地代价

理想终态要求改 runtime/channel 核心协议、抽离纯 reducer/adapter、调整 provider-neutral callback，并补真实 SDK 探针与事故家族测试；工作量显著高于局部修补。但不得用工作量压缩 UUID 探针、四类共享状态隔离或 ack 等待边界。
