# 背景与问题

审核 Claudian 2.6.1 真机暴露的历史索引、搜索、国际化与通知时序修复方案；基线为 `/Users/vincentwang/Documents/NoteVault/tools/claudian` 的 `eaf83afe6238d3ec38015d3c09f5dc4bd7ac962e`，结论是 **①③⑤需修订，②④成立，整体修订后可实施**。

# 方案设计

## 总览

| 项 | 结论 | 核心裁决 |
|---|---|---|
| ① 索引层单行降级 | 需修订 | 不能伪造普通 `user` entry 且清空 tool ids；须引入显式 opaque oversized entry，并用 discard-until-newline 状态机 |
| ② partial 不 fatal | 方案成立，但依赖①补边界 | 允许打开完整前缀；尾读起点必须是最后完整换行边界，不能用 snapshot EOF |
| ③ 搜索刷新加固 | 需修订 | 用一次 open 内的显式状态机与手动重试；不得让每次 input 重建；early return 返回结构化结果 |
| ④ i18n | 方案成立 | 覆盖全部用户可见裁剪/省略文案，不只 224/267 两处 |
| ⑤ 通知加固 | 需修订，⑤c 当前不足 | 不用时间窗口；用 transcript 顺序/身份信号。HEAD 已无所述 11–50s 退避；pending 仅在终结路径清零不能消除“结果永不到达”挂起 |

## ① 索引层单行降级：需修订

目标命中根因，但原方案的占位 entry 不成立：

- `/Users/vincentwang/Documents/NoteVault/tools/claudian/src/providers/claude/history/HistorySummaryProjection.ts:233-250` 只有 `toolResultIds.length > 0` 才生成工具结果占位；拟造 entry 的 `toolResultIds=[]` 会返回 `null`，只剩 turn 聚合 marker，原工具调用仍可能显示 running。
- 若 raw entry 按普通 `user` 参与 finalize，可能错误开启新 turn；若按 `skip`，又不能靠现有 `buildOversizedEntryPlaceholder` 完成工具配对。
- 缺失 `uuid/parentUuid` 会破坏 `/Users/vincentwang/Documents/NoteVault/tools/claudian/src/providers/claude/history/sdkBranchFilter.ts` 的 ancestry、rewind/fork `resumeAtMessageId` 截断及分支选择。不能声称 opaque 行仍保留精确 branch 语义。

修订设计：

1. 在 `RawIndexEntry`/`TranscriptIndexEntry` 墫显式 `oversized: true`（或独立 union），并固定：`projectionKind='skip'`、`realUser=false`、`displayable=false`。不要把未知行伪装成真实用户消息。
2. 若可在**有界内存**下从行前缀/增量 token 中可靠取得 `type/uuid/parentUuid/sourceToolUseID/message.content[].tool_use_id`，则写入这些字段；提取失败保持 unknown，不猜测。首选无新依赖的专用有限状态提取器；若实现复杂度不可控，允许只保留 opaque 位置并明确分支降级。
3. `scanSnapshot` 增加 `discardingOversizedLine`、`oversizedOffset`、`oversizedLength`。partial 超限后不再 `Buffer.concat`，逐 chunk 寻找下一 `\n`；找到后一次生成 opaque entry，再从换行后正常解析。仅清空 partial 而无 discard 状态会把超限行后半段误当新 JSON 行，否决。
4. `length` 必须覆盖整行、不含换行，与正常 entry 一致；`position` 每次按真实 `bytesRead` 前进；`lineNumber` 每遇换行只增一次。EOF 仍处于 discard 状态时**不得生成已提交 entry**，返回 partial，并把该行起点作为 `committedSize` 留给②/tail reader；待换行完成后的下一次索引再生成 opaque entry。
5. `line_skipped` 事件至少含 `reason:'oversized'|'malformed'`、`offset`、`bytes`、`mode`、`buildId`；禁止记录正文。当前 sink 是模块级单例，事件通过 `observeBuild` 注入 build context，避免 `scanSnapshot` 直接依赖全局时序。
6. worker 路径由函数序列化可继承扫描逻辑，但新增 helper、常量、union 字段必须逐一加入 `/Users/vincentwang/Documents/NoteVault/tools/claudian/src/providers/claude/history/ClaudeTranscriptHistoryIndex.ts:439-496` 的 eval source；“自动生效”只对已被序列化且无闭包依赖的函数体成立。
7. summary 遇 opaque oversized entry：始终生成“该 transcript entry 已省略”的独立可见占位；只有取得可靠 tool result id 时才额外生成 synthetic `tool_result`。未知关联不得伪造完成状态。
8. detail/search/fork/rewind：搜索不索引 opaque 内容；detail 返回 `too_large`/`not_found` 的明确降级；若 rewind/fork 锚点或必经 ancestry 落在 opaque 行，禁用该目标并显示既有 detail-too-large 类提示，而不是对可能错误分支执行操作。

更小方案是把上限提高到 32/64 MiB，但只是推迟故障且仍有硬崩边界，不推荐作为 3.0.0 终态。可作为紧急兜底测试，不替代上述降级模型。

## ② partial 不 fatal：方案成立，但须补快照边界

`/Users/vincentwang/Documents/NoteVault/tools/claudian/src/providers/claude/history/ClaudeConversationHistoryService.ts:298` 只对 `failed` 抛错是正确方向：搜索、分页、标题与窗口都可以在完整前缀上工作，结果语义是“截至最后完整行的前缀快照”。

必须补充：

1. index 增加 `committedSize`（最后完整 `\n` 后的 offset），与 `snapshotSize`（stat 时 EOF）分离。
2. `HistoryWindowPage.snapshotOffset` 返回 current segment 的 `committedSize`。否则 partial 被容忍后，observer 从 EOF 启动，会丢掉半行前缀，后续只读到后半行并永久解析失败。
3. `snapshotSize` 继续用于 cache identity/截断校验；`committedSize` 只用于 tail handoff。
4. partial index可用于搜索和分页，但 UI/诊断应标记 `partial_snapshot`；搜索结果只承诺完整前缀，不承诺当前正在追加的最后一行。
5. 多 segment 时，当前最后 segment 的 partial 属可恢复瞬时态；历史 segment 的 partial 也可展示完整前缀，但须诊断为 `stale_partial_segment`，因为它通常不会再补齐。

## ③ 搜索刷新加固：需修订

修改：

1. `/Users/vincentwang/Documents/NoteVault/tools/claudian/src/features/chat/controllers/ConversationController.ts:596` 返回 discriminated result：
   - `{status:'rebuilt'}`
   - `{status:'cache_hit'}`（若 service 能透传）
   - `{status:'not_applicable', reason:'no_lease'|'provider_without_index'|'no_conversation'}`
   - 真实 acquire/build 失败仍 throw。
2. Codex/OpenCode lease-less 搜索走 `/Users/vincentwang/Documents/NoteVault/tools/claudian/src/features/chat/controllers/ConversationController.ts:561-580`，`no_lease/provider_without_index` 是正常能力分支，不显示“快照滞后”。这也是 Codex lease-less 必须保留的边界。
3. `/Users/vincentwang/Documents/NoteVault/tools/claudian/src/features/chat/controllers/HistorySearchController.ts` 将 boolean 改为 `idle | refreshing | fresh | stale`：每次 open 首个非空查询最多自动 refresh 一次；失败进入 stale，继续搜索旧 lease，并显示“快照可能滞后”。后续 input/300ms debounce 只查旧快照，不再次 rebuild。
4. 同一 open 的重试只允许显式动作（状态旁 Retry 按钮，推荐），或关闭再打开搜索面板；成功后转 fresh 并重跑当前 query。不要按键自动重试，也不要固定时间循环重建。
5. `onStreamComplete` 仅在面板打开且 query 非空时触发一次 refresh；若与用户手动 refresh 并发，复用同一个 in-flight promise。
6. feature 诊断扩展 `/Users/vincentwang/Documents/NoteVault/tools/claudian/src/features/chat/history/HistoryDiagnostics.ts`：`search_snapshot_refresh`，字段 `outcome/reason/elapsedMs`；不要把 provider cache 细节硬编码到 controller。若确需区分 built/cache_hit，应由 history service 返回 acquire outcome，而不是 controller 猜测。

## ⑤ 通知加固：需修订

### a. 归属抑制

不采用毫秒窗口。固定窗口无法区分“延迟上报的旧 auto 完成”和“用户发送后真正完成的后台任务”。

推荐使用同一 transcript 内的因果顺序：

1. tail batch/mapper event 携带单调 `lineOffset`（或 reader-local sequence）。
2. runtime 将 host SDK user message 的 `uuid` 注册给 observer；observer看到该 transcript row 时记录 `lastHostUserOffset/hostEpoch`。
3. auto terminal candidate 记录 `terminalOffset`；settle 时若 `lastHostUserOffset > terminalOffset`，说明这是一条**已在新用户消息前完成、只是迟报**的 auto 轮。默认不要伪装成当前轮完成：若用户已在该 conversation 活跃则抑制；若 tab 仍在后台且产品仍需提醒，则改写为明确的“较早的后台任务已完成”，不能沿用普通“已完成”。
4. 真后台轮若 `terminalOffset > lastHostUserOffset`，即在新用户消息之后完成，照常通知。这样不靠毫秒窗口，也不误杀“用户先发消息、后台随后真正完成”。若“后台先完成、用户紧接着发送”仍要求保留通知，则只能采用上述改写而非抑制；这是产品裁决点。
5. `turnId` 只用于身份、幂等和 lease，不用于比较先后；host feature turnId 与 transcript UUID 不是同一命名空间。
6. 抑制/改写只作用于 `/Users/vincentwang/Documents/NoteVault/tools/claudian/src/features/chat/controllers/AutoTurnProjectionController.ts:425` 的 `onTurnCompleted`，不得跳过 auto 内容投影、save、lease finish/release。
7. host 仅“内存入队”但尚未落 transcript 时不据此压掉通知；否则因果顺序尚未建立。若产品明确把“用户重新参与会话”一律视为已读，可另行采用 enqueue epoch，但那是产品语义变更，不应混入 bug fix。

### b. 时滞收敛

按 HEAD，`/Users/vincentwang/Documents/NoteVault/tools/claudian/src/providers/claude/transcript/ClaudeTranscriptTailReader.ts:3,135` 是固定 2s poll，且 mapper 一旦在 `/Users/vincentwang/Documents/NoteVault/tools/claudian/src/providers/claude/transcript/ClaudeTranscriptTurnObserver.ts:147` 看到 terminal candidate，独立 2s quiet timer 已启动；不存在所述 11–50s idle backoff。因此“候选出现后退出退避”对 HEAD 是无落点方案，否决原表述。

若仍需降低 2–4s 延迟，采用轻量 wake：reader 增加幂等 `poke()`，在已知 runtime/host 活动或文件 watch 信号时取消下一 poll 并立即 tick；保留 2s quiet settle，空闲时仍按 2s polling。不要常驻 busy loop。是否引入 `fs.watch` 应先真机验证 Electron/Obsidian 下可靠性；否则维持 polling 更稳。

### c. `notificationResultPending`

在所有实际终结/重用入口清零是必要防御：

- `cancelTurn()` 在分支判断前清零，覆盖 user cancel、close、mismatch、异常收口；
- `settleTurnAtResult()` 消费或终结前清零；
- `reRegisterTurnForRetry()` 已清零，保留；
- projection barrier 的 `completeUserRuntimeHandoff()` 再做断言/清零；
- `settleColdStartTurn()` 理论上不会武装，但可用 invariant assert，不需业务分支。

但这**不能解决**“notification 自身 result 永不到达，随后用户轮 result 被吞”的地雷：在用户 result 到来前没有 terminal path 可执行强清。故 ⑤c 原方案不足，至少补一个可证伪机制后才能实施：把 boolean 改为带 `armedAt`、notification identity/sequence 的归属状态；当 transcript observer 或 SDK 流证明 notification turn 已结束/被后续 host user row越过时清除。若暂时拿不到可靠证据，宁可在超时后显式关闭并重建 persistent query、让既有 crash/retry 机制收口，也不要猜测下一条 result 的归属。该点本质属于已暂缓的双轨契约，不能用“终结时清 flag”伪装已修复。

## 依赖顺序与实施档位

顺序：

1. ①定义 oversized/committed boundary 数据契约；
2. ②消费 partial prefix，并把 `committedSize` 接到 observer；
3. ④接入新占位文案；
4. ③建立 refresh outcome/诊断与 UI 状态机；
5. ⑤独立实施，先冻结 transcript ordering 与 pending attribution 测试，再改 runtime/observer。

①②④强耦合；③只依赖索引能够成功返回；⑤与前三项无代码依赖，但与 turn lease/observer 事件契约强耦合。

实施档位：①②③④可由 `implementer-high` 分批完成；⑤涉及 runtime、observer、mapper、feature completion 的跨层归属 invariant，`implementer-high` 不足，建议 `implementer-opus-xhigh`。五项不应一次混成单批提交。

# 风险与权衡

1. ①若无法可靠提取 oversized 行的 uuid/parentUuid，分支过滤只能降级；必须显式禁用受影响的 rewind/fork，不得假装结构完整。
2. opaque tool result 无可靠 id 时，不能把未知工具强制标 completed；允许显示 turn/entry omission marker，优先保证事实正确。
3. partial 可用不等于完整；搜索计数和分页范围只覆盖 committed prefix。
4. ③的 stale warning 应与搜索结果同时存在，不能用 fatal error遮住仍可用的旧快照。
5. ⑤若坚持既不误杀“真后台完成”又要压掉“旧完成与新发送撞车”，必须用 transcript 因果顺序；仅 timestamp/window 无法同时满足。
6. `setTranscriptIndexDiagnosticSink` 是模块级单 sink；当前多 service/多 vault 场景可能后初始化覆盖先前 sink。本次可不扩大范围，但新增诊断不得进一步依赖隐式全局 build context。

# 验证方式

## 自动化

1. `ClaudeTranscriptHistoryIndex.test.ts`
   - oversized 完整行位于单 chunk、跨 2/3+ chunk、紧邻换行、EOF 无换行；验证 offset/length/lineNumber、下一行可解析。
   - direct 与真实 worker 输出深相等；worker eval 新 helper 不缺失。
   - malformed 与 oversized 诊断原因分离，正文不入日志。
   - oversized 行位于 fork ancestor、resume target、alternate branch；验证禁用/降级而非选错分支。
2. `ClaudeConversationHistoryService.test.ts` / `HistoryBudgetMaterialization.test.ts`
   - opaque entry 可见 marker；有可靠 tool id 时 tool result 配对，无 id 时不伪造完成。
   - partial 返回 prefix；`snapshotOffset===committedSize<snapshotSize`；补齐尾行后刷新得到完整索引。
   - partial 搜索/分页不越过 committed boundary。
3. `HistorySearchController.test.ts` / `ConversationController.test.ts`
   - 首次 refresh 失败：旧 lease 仍可搜索、显示 stale；连续输入不重复 acquire。
   -显式 Retry 只触发一次；并发 retry/onStreamComplete 合并。
   - `no_lease/provider_without_index` 的 Codex/OpenCode 路径无 stale 警告并继续 DOM 搜索。
   - built/cache_hit/early-return/failed 均有诊断。
4. `HistorySummaryProjection.test.ts` 与 i18n 测试：10 locale 五类 marker 均解析；切 locale 后新物化使用新文案；search corpus 不含 marker。
5. `ClaudeTranscriptTailReader.test.ts` / `ClaudeTranscriptTurnMapper.test.ts` / `ClaudeTranscriptTurnObserver.test.ts` / `ClaudianService.test.ts` / `AutoTurnProjectionController.test.ts`
   - auto terminal offset < 后续 host row offset：只抑制完成通知，不抑制投影/save/release。
   - host row先、后台 auto 后完成：通知一次。
   - wall-clock 相邻但 transcript 因果无 supersede：不误杀。
   - notification result 正常到达、永不到达、cancel、abort、consumer exception、restart/replay 各路径均不吞 host result且 lease最终释放。
   - `poke()`（若采用）合并重复唤醒，空闲无高频轮询。

## 人工核对

- 用原 16.87MB transcript 打开、搜索、翻页；对应 turn 显示本地化省略提示，其他 turn 正常。
- 在写入半行期间打开，再补齐；首次显示完整前缀，后续刷新纳入新行且 observer 不丢事件。
- 搜索 refresh 注入一次失败：同一 open 持续输入不重建；点击 Retry 后成功。
- 复现“旧 auto 完成后立即发新消息”：无错误完成通知；后台任务确在新用户行后完成时仍通知。
