# Claudian v6 生产回归诊断与修复（务实）

## 背景与问题

v6 上线后出现 external 气泡重启丢失与一次约 19 分钟的 Obsidian 全 tab 无响应；需先消除已证实的数据源判定分裂和 mid-turn 错误归属，并为无法由现存证据唯一还原的 renderer 级冻结补齐可复现测试与诊断边界。授权依据：用户指令“定位下原因”及本次明确要求方案落设计记录；本记录为新建，不修改既有 v6 记录。

## 方案设计

### 1. 根因结论

#### 1.1 气泡丢失：已确定

实时链在 `/Users/vincentwang/Documents/NoteVault/tools/claudian/src/providers/claude/transcript/ClaudeTranscriptTurnMapper.ts:66-75` 按 `origin.kind` 接受 peer/channel/coordinator；恢复链却在 `/Users/vincentwang/Documents/NoteVault/tools/claudian/src/providers/claude/history/sdkMessageParsing.ts:314-320` 无条件把 `isMeta:true` user 当系统注入过滤。现场 peer 行同时满足 `origin.kind='peer'` 与 `isMeta:true`，故实时可见、重启必丢。`.claudian` 元数据按设计不存 native session messages（`SessionStorage.toSessionMetadata():102-123`），不是第二份消息真相源。

#### 1.2 冻结主假设：不成立；确定存在 mid-turn 错误归属

现场 1070 peer user 被 mapper 开为 external turn；1072/1073 是同一宿主活跃 turn 的 assistant `end_turn`。mapper 不识别宿主 turn，直接把后者归到 peer，并在 `/ClaudeTranscriptTurnMapper.ts:155-165` 产生 `finished`。observer 随后按 `/ClaudeTranscriptTurnObserver.ts:140-148` 调 `finished → promote → released`；controller 又在 `/AutoTurnProjectionController.ts:175-198` 的 `finally` 执行 `finish`。因此“该 peer 无结束行导致 lease 永不释放”与现场行序、代码均矛盾。

确定缺陷是：mid-turn external 被误开成独立 auto turn，并盗用宿主 assistant 作为其输出；这会重复投影/保存并制造不必要 lease，但该样本自身有终态。

#### 1.3 全 tab 冻结：现存证据不足以唯一归因

`TurnCoordinator` 在 `/TurnCoordinator.ts:41` 是 tab 实例字段，不能直接冻结其他 tab。TailReader 每批最多 2MB，并在追批间 `setTimeout(0)`（`/ClaudeTranscriptTailReader.ts:61,100-107`）；现场 1070-1081 增量约 15KB且 1081 后停止增长，不能形成 19 分钟 busy-loop。`onBatch` 抛错只会结束该 async tick并在 finally 后 2s 重排，不会同步自旋。

但有两个真实挂死孔：`ClaudeTranscriptTurnObserver.drainActive():140-148` 对 chunk/finished 异常无补偿，及 `AutoTurnProjectionController.finished():184` 对永不 settle 的 save 无取消边界；二者可挂本 tab lease，仍不能单独解释全 tab。console 已因重启丢失，故不得把全 tab 现象伪定性为某一孔；先回滚，再用红测和低成本诊断确认 renderer 阻塞点。

### 2. 修复

1. **立即回滚生产**：用 `/Users/vincentwang/Documents/NoteVault/.obsidian/plugins/claudian/main.js.bak-20260911-pre-v6` 与同目录 `styles.css.bak-20260911-pre-v6` 恢复，重启 Obsidian；保留源码/现场 transcript，不在生产继续冒烟。
2. **hydration 对齐**：抽取 `isDisplayableExternalUser(message)`，仅允许 `type=user && origin.kind∈{peer,channel,coordinator} && uuid/msg_id存在` 穿透 `isMeta`；仍优先过滤 `toolUseResult/sourceToolUseID`，正文统一复用 `extractExternalDisplayContent`，空/残缺信封 fail-closed。`parseSDKMessageToChat` 对该类 user 写净化后的 `content/displayContent`，不得暴露 socket/PID/msg_id。
3. **不新增 `.claudian` 消息持久化**：Claude native transcript 继续是消息唯一真相源；双写会引入去重、分支、rewind 和崩溃一致性问题。`.claudian` 只存 metadata。
4. **mid-turn 归属修正（mapper 保持纯输入驱动）**：不让 mapper 读取 feature/observer 状态；由 observer 向每次映射显式传上下文。
   - `/Users/vincentwang/Documents/NoteVault/tools/claudian/src/providers/claude/transcript/ClaudeTranscriptTurnMapper.ts` 增加：
     ```ts
     interface TranscriptMapContext { hostUserTurnActive: boolean }
     type TranscriptTurnEvent = /* 既有三类 */
       | { type: 'embedded'; event: AutoTurnStartedEvent };
     mapLine(line: string, replay?: boolean, context?: TranscriptMapContext): TranscriptTurnEvent[];
     map(message: SDKNativeMessage, replay?: boolean, context?: TranscriptMapContext): TranscriptTurnEvent[];
     ```
     默认 `hostUserTurnActive=false`，保持现有测试兼容。遇 external user 且该值为 true 时只产出 `embedded`，**不得设置 `mapper.active`**；故同行之后的宿主 assistant/tool/result 在 mapper 中无 external active 可归属，继续只由既有 SDK stream 投影。false 时才产出 `started` 并设置 active。
   - 不能仅在 poll 时读取 `TurnCoordinator.isBusy()`：poll 可能晚于宿主结束。增加显式生命周期握手到 `/src/core/runtime/ChatRuntime.ts`：
     ```ts
     beginUserTurnProjection?(turnId: string): void;
     completeUserTurnProjection?(turnId: string): Promise<void>; // 既有签名
     ```
     `InputController` 在 `beginUserTurn()` 成功后、任何 query 前调用 begin；Claude runtime 转发到 observer。observer 保存 `hostUserTurnId: string | null`。complete 时先串行执行一次 reader catch-up（与 poll 共用 `consumeChain: Promise<void>`，禁止并发 read/consume），该批映射仍传 true；然后清 host id、投影 embedded FIFO、再按现有顺序晋升独立 external FIFO。turnId 不匹配则 fail-closed，不清状态。
   - observer 增加 `embeddedQueue: AutoTurnStartedEvent[]`；embedded 不调用 auto-turn callbacks。新增 feature 回调：
     ```ts
     projectEmbeddedExternal(event: AutoTurnStartedEvent): Promise<void>;
     ```
     runtime callback由 `Tab.ts` 接到 `AutoTurnProjectionController.projectEmbeddedExternal()`：仅按 `transcriptUserId` 幂等插入净化 user bubble，插在当前宿主 assistant message 之前，不创建 assistant、不碰 `currentContentEl/isStreaming`、不取得 lease；批量插完调用一次 `ConversationController.save(false)`。
5. **异常与 save 永不 settle 的确定兜底：选择（b）到时取消等待并放行 feature lease**。
   - `drainActive` 以 turn 为单位 catch；任何 chunk/finished callback reject 都调用 `cancelled(interrupted=true)`、清 active、继续 FIFO，最终由既有 `cancelAutoTurn` 清 lease。
   - `AutoTurnProjectionController.finished()` 的 finalize/render 仍不设超时；只对 `conversationController.save(true)` 使用 `SAVE_SETTLE_TIMEOUT_MS = 5_000` 的 `Promise.race`。5 秒到期后定义为 `save_timeout`：保留已经写入 `ChatState/DOM` 的完整投影，设置 `state.hasPendingConversationSave=true`，显示一次 notice，执行 `resetStreamingState → active=null → turnCoordinator.finish(turnId)`；observer 随后正常 `released(turnId)`，用户队列恢复。
   - Obsidian adapter write 无 AbortSignal，所谓“取消”只取消 controller 的等待，底层 Promise 不可物理中止；必须给原 save Promise 挂 `.catch(record)` 防止 unhandled rejection，但不得在其迟到完成时再次 finish/release/notify或启动新保存。`hasPendingConversationSave` 在 timeout 分支最后重置为 true（即使底层 save 曾同步改 false）；后续既有 tab 切换保护/下一次正常 `ConversationController.save()` 复用该标志完成重试。不得从 timeout handler 后台主动重试，避免制造第二次并写。
6. **TailReader 限额**：每 tick 常量 `MAX_BATCHES_PER_TICK=4`、`MAX_BYTES_PER_TICK=8*1024*1024`；达到任一预算后 `setTimeout(tick, 0)` 续读，空闲轮询仍为 2 秒。`onBatch` reject 记录诊断并结束本 tick，下一次按 2 秒重试，不产生 unhandled rejection。
7. **P0 诊断 ring-buffer 规格**：新增 `/Users/vincentwang/Documents/NoteVault/tools/claudian/src/providers/claude/transcript/ClaudeTranscriptDiagnosticLog.ts`，运行文件固定为 vault 内 `.claudian/diagnostics/transcript-tail.current.jsonl`，上一段为 `transcript-tail.previous.jsonl`；重启后可直接读取，禁止写 plugin 安装目录或 console。
   - 接口：
     ```ts
     type TranscriptDiagnosticPhase = 'tick_start'|'tick_end'|'map'|'lease_begin'|'lease_finish'|'lease_release'|'render_start'|'render_end'|'save_start'|'save_end'|'save_timeout'|'callback_error';
     interface TranscriptDiagnosticEvent { phase: TranscriptDiagnosticPhase; tabIdHash?: string; turnIdHash?: string; generation?: number; leaseKind?: 'user'|'auto'; batchBytes?: number; batchLines?: number; elapsedMs?: number; errorName?: string }
     class ClaudeTranscriptDiagnosticLog { record(event: TranscriptDiagnosticEvent): void }
     ```
   - 单条经白名单序列化，附 `ts` 与单调 `seq`，UTF-8 后最多 1024 bytes；严禁正文、路径、socket、PID、msg_id、错误 message/stack。turn/tab ID 仅存进程内随机 salt 的 SHA-256 前 12 位，重启后不可反推。
   - **每事件同步落盘**：`record()` 使用 Node `appendFileSync`；这是冻结前最后阶段取证的核心，不使用内存 buffer、debounce 或异步 flush。每条上限 1KB且仅打生命周期边界，不记录 chunk 正文/逐 token，控制主线程成本。
   - 双段有界轮转：写前 `statSync(current)`；若 `size + entryBytes > 128*1024`，先删除 previous，再 rename current→previous，再创建 current；总上限约 256KB。任一 I/O 异常只熔断本次插件生命周期的诊断器并发一次 Obsidian Notice，不得影响 turn。
   - Claude runtime 持有每 tab/session 一个 logger；observer 直接记录 tick/map/callback，feature 层通过 `ChatRuntime.recordAutoTurnDiagnostic?(event)` 转发 lease/render/save 边界，不在 provider-neutral controller 中引用 Claude logger。

## 风险与权衡

- display-only bubble 以宿主 turn 创建的 assistant message ID 作为插入锚点；若锚点因 lifecycle 切换已不存在则丢弃该 embedded 投影，由 hydration 恢复，禁止追加到错误会话尾部。
- hydration 豁免必须同时覆盖 branch fixture；`sdkBranchFilter.ts` 的“real user”判定同步改为复用 external user 分类，否则 external meta 行仍可能被分支裁剪。
- 5 秒 save timeout 是 feature 可用性兜底，不声称中止底层 I/O。迟到 save 与后续 save 可能发生底层写入交叠；现有 metadata 写入是整文件覆盖，因此 timeout 后只允许用户后续正常生命周期触发重试，不主动后台续存，并以 `hasPendingConversationSave=true` 防止 tab 被安全回收。
- 同步诊断 append 是 P0 期间的刻意取舍：每事件可持久取证优先于极小 I/O 开销；根因确认后可另案降级或移除，不进入逐 token 热路径。
- **迁移/落地代价**：涉及 mapper、observer、history parser、runtime 生命周期接口、projection callback 与测试；但不引入第二消息存储。

## 验证方式

1. 红测使用现场 1067-1081 最小 fixture：先 `beginUserTurnProjection(host)`，再 append peer，最后 complete；断言 mapper 只产 `embedded`、`hasOpenTurn=false`、`beginAutoTurn=0`、气泡在宿主 assistant 前且仅一份、宿主 assistant 不重复、最终 lease 空闲。补“peer 已落盘但 poll 未运行，complete catch-up 后才清 host”竞态测试。
2. hydration：`isMeta peer/channel/coordinator` 可恢复；普通 isMeta、tool_result、attachment 仍过滤；分支/rewind fixture 保留 external 行；重启前后消息序列一致。
3. 故障注入：chunk/finished callback reject 均 cancelled 并释放；save reject 立即释放；save 永不 resolve 时 fake timer 4,999ms 仍持 lease、5,000ms 后 `save_timeout`、`hasPendingConversationSave=true`、finish/release 各一次、queued user 被 pump；迟到 resolve/reject 不产生第二次副作用或 unhandled rejection。
4. 诊断：每次 `record()` 后立即读取 current 即可见；超过 128KB 后 current/previous 均存在且总量≤约256KB；事件字段白名单和 1KB 上限生效；写盘失败只熔断日志、不影响 turn。冻结模拟在 `save_start` 后停推进，重启后文件末条仍为 `save_start`。
5. TailReader：持续增长超过 8MB时每 tick 最多4批/8MB并让输入 timer 获得执行；onBatch reject 不产生 unhandled rejection或零延迟重试。
6. 全门：`npm run typecheck && npm run lint && npm run test && npm run build`；部署后先单 tab mid-turn 冒烟，再多 tab，读取 `.claudian/diagnostics/transcript-tail.current.jsonl` 核对阶段闭环，不直接恢复全量生产。
