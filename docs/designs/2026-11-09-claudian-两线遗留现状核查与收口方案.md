### 3. 收口计划（按依赖排序）

**阶段 0：串行闸门**——等 #1482 完成通知；全套 unit/integration/typecheck/lint 门禁跑一次，建立共享树测试基线，把 13 红（集成 suite）+5 红（Tab.test.ts，W4c/S3/Escape 在途）按归属清算：A/B 用例挂账给 R2，12 R1a 漂移例由在途线收尾回归或 integrator 统一修。**不得把 13 红误判为 R1a 回归而重修 R1a**（R1a 代码在位，红因是后续线漂移）。

**阶段 1：R2 binding 接线**（P6-0→生产保存流程；唯一 integrator 串行）——改 `ChatState.ts`（PreparedHistory+短同步提交+CommitReceipt）、`ConversationController.ts`（loadActive/switchTo/restore/createNew 改 prepare→commit→adoption→通知）、`main.ts`（旧隐式 hydrate 退役）、Codex/OpenCode history service 返回 PreparedHistory。**验收**：P6 文档 §6.2 逐项+新 `tests/unit/app/ConversationHistoryCoordinator` 生产镜像+集成 suite 中 A/B rebind 用例转绿（firstSession=fixture-session-a）。此步同时修复 B 线挂账的 A/B 用例。

**阶段 1 实施留痕（2026-11-10 订正）**：实际落地为 binding/seal/回执形态（`ConversationMetadataSavePort` + adoption），达成同等保存绑定目标，形态与原列方案不同、目标等价。原列 PreparedHistory 轴（`ChatState.ts`、Codex/OpenCode history service 返回 PreparedHistory、`main.ts` 旧隐式 hydrate 退役）未在本阶段实施，并入后续 hydration 阶段（R1h 线）。阶段 1 复核确认的已知偏离（挂账后续，不在本阶段修）：①空会话 reset 偏离（L607/729）；②TabManager drain 后 save（L1973）；③deleted-record 弃旧 owner 不 drain；④A/B 用例在他线（W4d/#1482 收尾）影响下先于 R2 转绿，绿因归属须按此说明解读，不作 R2 单独修复证据。

**阶段 2：S 接线**——新建 `src/core/storage/PersistenceCoordinator.ts`（同宿主 App+namespace 写序、读屏障），接 `SessionStorage.ts`/`SharedStorageService.ts`/provider storage adapter/main；验收=跨实例写序/失败 reject/lazy 新 ID 进最终 layout（P6 文档 §6.4）。

**阶段 3：T1 收尾**——T1a 独立复核；P5 recovery 3 个开放失败补齐；**前置裁决**：missing/换源重试策略、超长未闭合行政策（见 §5 裁决 3）。

**阶段 4：H/P8 source 移交**——`ClaudeConversationHistoryService` 导出 source-chain/segment/dev/ino/committedOffset descriptor，中立 `HistoryWindowPage.tailStart`，Reader/Observer/Controller/runtime 贯通；新 `tests/integration/features/chat/historyTailHandoff.test.ts`。**验收**：第二处换源缺陷（prime 裸 offset）转 source-changed 拒绝。

**阶段 5：R1b 闭合**——R2 完成后：R3-resource（真实 exit barrier 红测）→ G-domain/G-exit 实证（Electron reload/窗口域核查）→ 重写 R1b 合同 → 独立复核 → 实施。当前不预支。

**阶段 6：B 线证据闭环**（与 1–5 并行准备，部署后执行）——获部署授权后部署，真机采期 0 证据（冷启动/长历史/后台流式/真实卡死现场），分析 `.claudian/diagnostics/` markdown-render 日志+DOM census，出根因结论；据此重修期 1–4 设计再报批准。**先诊断后实施，本轮不预设根因**。

### 4. 推演

**论证链**：A/B 用例红→根因=保存绑定缺口→R2 接线修复。前提①：缺口定性正确（开关对照已证非 B 诊断）；前提②：rebind 场景实机可达（未证实，测试延长微任务窗口人为放大）。反例：若实机 rebind 不发生，R2 修复后该用例转绿但实机无感——不推翻 R2 必要性（R2 的价值在统一合同本身）。

**结构不变量**：阶段序 R2→S→H→R1b 无环（R1b 依赖 R2 稳定 owner，takeover 记录已证非循环：R1b 不等完整 result 识别）；binding/save receipt/资源 exit 分轴正交；入口覆盖沿用 takeover 记录恢复全入口矩阵。

**具象走查**：A/B 用例绿判据=R2 后 outgoing 保存 payload 在首 await 前冻结于 A 的 runtime capture，close 时 written 元数据 sessionId=fixture-session-a；红=若接线后 payload 仍读 live runtime，用例仍红。

## 风险与权衡

- **共享树继续漂移**：阶段 0 前在途线仍可能改动，两线 owned patch（/tmp/claudian-i1-*/I1-owned.patch 等）须在应用前重对拍 hash；I1 patch 对 main 不可直接应用一事在合并阶段重处理。
- **R2 是最大单体**：P6-0 核心虽 PASS 但 §6.2 生产接线横跨 4+ 文件与三 provider，建议 implementer-max+独立 reviewer；P6 文档正文未回填 'none' 分支等后续裁定，实施以裁定后合同为准。
- **B 线部署依赖**：期 0 取证被"未部署"卡住，而部署又依赖共享树进入可交付状态——实际关键路径仍是竞态线阶段 0–2；若用户想先看性能证据，可单独裁决"仅含 B/A/Stop 已复核项"的最小部署集，代价是分两次部署。
- 不确定处：12 个 R1a 漂移例的逐例归属（修在 W4d/S3/#1482 收尾还是 integrator 统一修）待阶段 0 基线跑完按 diff 归属判定。
