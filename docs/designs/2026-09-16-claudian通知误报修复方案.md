# 背景与问题

> 实施记录（2026-09-16）：已实施（dc32dccb + 尾修 effea3f2，2.3.0 部署，复核通过）。

Claudian 把 `ChatState.isStreaming=false` 的任意赋值当成“后台轮次成功完成”，而该字段同时承担 UI 忙闲复位、失败清理、租约取消和生命周期失效，故 query 刚启动后若走前置失败/取消复位即可误发“已完成”。

# 方案设计

## 1. 根因与三种时点判定

确切触发链为：

1. `/Users/vincentwang/Documents/NoteVault/tools/claudian/src/features/chat/state/ChatState.ts` 的 `isStreaming` setter 每次赋值都调用 `onStreamingStateChanged`，既不判断旧值，也不携带 turn id、结束原因或成功终态。
2. `/Users/vincentwang/Documents/NoteVault/tools/claudian/src/features/chat/tabs/TabManager.ts` 的回调只判断 `!isStreaming && 后台 tab && !cancelRequested`，直接设置 `needsReview` 并调用 `streamComplete` 通知。
3. `false` 不只来自成功结束：`InputController` 在 live projection lease 等待取消、runtime 初始化失败、外层防御清理等路径也赋值；`TurnCoordinator` 在 auto turn finish/生命周期失效时也赋值；`ConversationController.createNew` 还可对本来就是 false 的状态重复赋值。`cancelRequested` 只是瞬时 UI 标志，且若先被清零再赋 false，也无法证明成功。

三种用户表述的判定：

- **① query 启动/流式刚开始：确认是主触发面。** 新增 `ProjectionWriteCoordinator` 后，send 会先置 `isStreaming=true`，再等待 live projection lease；等待被 generation/turn lease 取消时立即写回 false。只要期间该 tab 已变为后台，现逻辑就把“启动失败/取消复位”误报为完成。runtime 冷启动失败及其他前置异常同理。具体现场落在哪个 early-exit 分支，现有通知无 turn/outcome 诊断，不能仅凭用户描述唯一化；但共同根因已由调用链确定。
- **② tab 打开/会话水合完成：普通历史物化与 READY 转换本身不写 `isStreaming`，因此不会直接触发。** `handleTabHistoryLoadProgress` 的 READY 门控只控制占位符。Claude transcript observer 有恢复未闭合外部 turn 的能力，此时发生的 started→finished 是恢复中的真实 auto turn，不是“历史消息完成通知”；完整历史终态不会被 recovery 重放。故排除“READY 把历史完成消息直接误判”为当前主因。
- **③ 切 tab/失焦恢复：单独切 tab、activate/deactivate、窗口失焦均不写 `isStreaming`，不能独立触发。** 但切 tab 会改变 `activeTabId`，把随后到达的任意 false 复位暴露成后台通知，是竞态放大条件；因此“切走后立刻收到”仍归入①的错误终态来源，而不是 tab 状态转换自身。

这不是通知 debounce 或 OS 重复投递问题，也不是 ProjectionWriteCoordinator 租约重复释放；租约改造只是新增了一个合法的“启动后取消并回到 idle”路径，暴露了通知把 UI 状态误当业务事实的旧设计缺陷。

## 2. 方案比较

| 方案 | 做法 | 优点 | 缺点 | 结论 |
|---|---|---|---|---|
| A. setter 做 true→false 边沿判断 | `ChatState` 记旧值，仅下降沿回调 | 改动最小，可挡住重复 false | 启动后失败/租约取消仍是 true→false，继续误报 | 否决 |
| B. TabManager 增加 started latch/debounce | true 时置 latch，false 时消费；可加最短时长 | 易落地 | 仍无法区分成功、失败、取消；短任务会被误杀，时间不是语义 | 否决 |
| **C. 通知改订阅显式轮次终态（推荐）** | UI busy 状态只管展示；用户轮/auto turn 在确认成功终态后上报 typed completion event | 根治状态误判；与租约、水合、tab 切换解耦；可按 turn id 防重 | 需改两类轮次控制器及装配测试 | **采用** |

## 3. 推荐设计：通知只消费成功终态事件

### 3.1 新契约

在 `/Users/vincentwang/Documents/NoteVault/tools/claudian/src/features/chat/tabs/types.ts`（若只在 Tab 装配内使用，也可定义于 `Tab.ts`）增加 provider-neutral 事件：

```ts
type CompletedTurnEvent = {
  turnId: string;
  kind: 'user' | 'auto';
  outcome: 'completed';
};
```

首版只暴露可通知的 `completed`，不要把 `isStreaming=false` 包装成新名字。失败、用户取消、generation 失效、projection lease 未取得、observer interrupted 均不发事件。通知层无需理解 provider result 细节。

`TabCreateOptions` 增加内部回调 `onTurnCompleted(event)`；由 `initializeTabControllers` 分别注入 `InputController` 和 `AutoTurnProjectionController`，最终回到 `TabManager`。`ChatState.onStreamingStateChanged` 保留给 tab UI/外部状态同步，但彻底移除通知与 `needsReview` 的业务判断。

### 3.2 用户轮完成点

修改 `/Users/vincentwang/Documents/NoteVault/tools/claudian/src/features/chat/controllers/InputController.ts`：

1. **[修订 2026-09-16｜来源：独立审核]** 引入 turn-local `providerCompletedNaturally=false`；仅在 `for await (runtime.query(...))` 自然耗尽后置 true。当前 query 异常在 `InputController.ts:514-521` 被吞并继续 cleanup，故 catch、cancel break、generation invalidation、未取得 projection lease、初始化失败均必须保持 false，不能把“走到 cleanup”当成功。
2. `InputController.ts:574-575` 的 thinking/text finalize 不是完成事件发射点。只有同一 `turnId + streamGeneration` 仍有效、未取消、`providerCompletedNaturally===true`，且 `InputController.ts:699-731` 的最终 dirty 重投影成功后，才调用一次 `onTurnCompleted({ turnId, kind:'user', outcome:'completed' })`。
3. 最终 dirty 重投影失败、被取消或判 stale 时不上报；事件必须位于该成功闸门之后，避免“通知已完成、最终正文仍未挂载”。conversation save 仍不作为完成门槛：回复已最终投影时，即使持久化失败也可通知。
4. 事件设 turn-local once guard，防 finally、重入或后续回调重复上报。

### 3.3 auto turn 完成点

修改 `/Users/vincentwang/Documents/NoteVault/tools/claudian/src/features/chat/controllers/AutoTurnProjectionController.ts`：

1. 仅 `finished(event)` 的当前 `turnId + generation` 路径、mount/replay/finalize 成功后进入完成候选。
2. **[修订 2026-09-16｜来源：独立审核]** `reprojectIfDirty()` 改为返回显式成功状态：无需重投影视为成功；实际重投影完成为成功；stale、取消或异常为失败。当前 `AutoTurnProjectionController.ts:392` 调用链会吞掉重投影异常，事件必须在返回成功后才发射，不能依据“finally 已执行”推断完成。
3. `cancelled`、`abortActive`、`finalize_timeout`、observer `interrupted` 不上报。
4. save 失败仍可在最终投影成功后上报；既有“可见但未保存”Notice 独立保留。
5. 利用 controller 当前 active turn 身份保证一次性；不得在 `TurnCoordinator.finish()` 的通用 idle 复位处通知，因为 finish 同时服务取消/失效。

### 3.4 TabManager 策略与防重

修改 `/Users/vincentwang/Documents/NoteVault/tools/claudian/src/features/chat/tabs/TabManager.ts`：

- `onStreamingChanged` 只透传 `onTabStreamingChanged`，不再设置 `needsReview`、不再通知。
- `onTurnCompleted` 到达时再读取**当时**的 `activeTabId`：若 tab 为后台，则设置 `needsReview=true` 并通知；若为前台则不通知。
- 每 tab 维护有界的最近完成 turn id（推荐仅保存 `lastNotifiedCompletedTurnId`；turn id 单调唯一，无需 Set），相同 turn 重放不重复通知。切换 tab 只清 `needsReview`，不清防重 id。
- `needsAttention` 继续使用独立 attention edge，不纳入本次完成事件；其 `beginAttention/endAttention` 已有计数语义。

### 3.5 notifier 边界

`/Users/vincentwang/Documents/NoteVault/tools/claudian/src/features/chat/tabs/desktopNotifier.ts` 继续只负责设置、权限、i18n 与 OS API，不承载轮次判断或 debounce。该模块不是根因，避免把业务状态机塞进通知适配器。

# 风险与权衡

1. **现场具体 early-exit 尚未唯一化。** 代码已证明所有 false 路径都会误报；但若要确认本次用户现场究竟是 projection lease 取消还是 runtime 初始化失败，应在测试版给 completion suppression 增加结构化诊断（`turnId/kind/reason/generation/tabActive`），不要靠延时猜测。
2. **“完成”定义必须固定。** 推荐定义为“provider stream 正常终止，且最终可见投影完成”；conversation save 不作为完成门槛。否则慢磁盘会延迟通知，save 失败会让已经可见的回复永不通知。
3. **极短真实回复不能按耗时过滤。** debounce/min-duration 会误杀真实秒级结果，因此不采用。
4. **auto turn replay。** observer 的 replay 只应用于恢复中的未闭合 turn；仍以 turn id 防重，避免 observer 重启或重复 finished 回调产生通知。若产品最终希望“插件启动时恢复完成的后台任务不通知”，需再给事件增加 `replay` 策略并明确裁决；本次不擅自改变该产品语义。
5. **与 B1/P1-P7 的关系。** 不修改 projection lease、READY 门控或 hydration 数据流；它们只决定投影何时可写。通知从该底层状态中解耦，后续 B4/DOM 窗口化不应再触碰完成判定。
6. **[修订 2026-09-16｜来源：独立审核] Provider 兼容性。** `turnId` 由 `Tab.ts:1941-1943` 的共享装配链生成并跨 provider 稳定；Codex/OpenCode 用户轮均经过 `InputController`，因此共享成功闸门适用。两者 auto callback 当前为空实现，新增 auto 完成回调不得改其行为。

## 人工时序验收

逐项执行并观察系统通知：

1. 后台 tab 正常完成：一条“已完成”。
2. 发送后立即切到另一 tab：只有真实回复完成时通知，不在 query 启动/等待 lease 时通知。
3. 在 stored hydration/search transaction 排队时发送，再切 tab；让 live lease 等待取消：零条完成通知。
4. Obsidian 冷启动恢复历史 tab、打开大历史、READY 后后台索引继续：零条完成通知。
5. 单纯切 tab、窗口失焦/恢复：零条通知。
6. 用户取消、runtime 初始化失败、query 抛错：零条“已完成”。
7. auto turn 正常结束一条；observer interrupted/replaced 零条。
