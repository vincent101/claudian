# Claudian 阶段 2 空闲期管道回喂实施设计 v2

> 已被 [[2026-08-22-Claudian阶段2空闲期管道回喂实施设计-v3]] 替代。v3 补齐 MessageChannel 外部 turn、可实现的 restart/cancel 契约、conversation 单写者和完整保存语义。

## 背景与问题

阶段 1 已确立 task-notification 为异步任务终态权威销账信号；阶段 2 按理想架构把 SDK 的用户轮、task-notification 自动唤醒轮、Stop hook block 续轮统一成有明确所有权和生命周期的 turn，再复用同一条 feature 消费管道，消除 handler 猜归属、全局流状态、DOM 依赖和后台保存阻塞。

## 方案设计

### 1. 已确认现状与 v1 失效点

管道主体沿用 [[2026-08-22-Claudian阶段2空闲期管道回喂实施设计]] §1，不重抄。补充四个决定实现边界的源码事实：

1. `/src/providers/claude/runtime/ClaudeChatRuntime.ts:queryViaPersistent()` 在 `MessageChannel` 真正 dequeue 前已经 `resetTurnMetadata()`、创建并注册 `ResponseHandler`、再 `enqueue()`。因此“首个 SDK chunk 到达时是否存在 handler”不等于该 handler 已取得 turn。
2. `/src/providers/claude/runtime/ClaudeMessageChannel.ts` 只在 `enqueue()` 直接交付或 async iterator `next()` 从 queue 取出时把 `turnActive=true`；这两个点才是用户 turn 的真实开始。
3. `/src/features/chat/controllers/InputController.ts:sendMessage()` 在调用 runtime 前已依次设置 `isStreaming=true`、创建 user/assistant state 与 DOM、改写 `currentContentEl`。auto turn 若未先占 feature 层排他权，用户发送会立即覆盖其渲染上下文。
4. `resetTurnMetadata()`、`closePersistentQuery()`、`applyDynamicUpdates()` 当前操作全局 `turnMetadata`、usage transform state、`_autoTurnBuffer` 与去重标志。提前注册用户 query 或 config restart 都可能清除正在收集的 auto turn。

结论：v1 的“首消息时锁定最后一个 handler”不足以确定归属；必须以 dequeue 事件签发 turn lease，并在 runtime 与 feature 两层共同仲裁。

### 2. 统一 turn 模型

#### 2.1 RuntimeTurn

在 `/src/providers/claude/runtime/types.ts` 定义 Claude provider 内部类型，不上浮到 provider-neutral `StreamChunk`：

```typescript
type RuntimeTurnKind = 'user' | 'auto';
type RuntimeTurnPhase = 'queued' | 'collecting' | 'projecting' | 'settled' | 'cancelled';

interface RuntimeTurn {
  id: string;
  kind: RuntimeTurnKind;
  phase: RuntimeTurnPhase;
  generation: number;
  handler?: ResponseHandler;       // user turn only
  chunks: StreamChunk[];           // auto turn only
  metadata: ChatTurnMetadata;
  bufferedUsage: UsageChunk | null;
  streamState: TransformStreamState;
  usageState: TransformUsageState;
  sawStreamText: boolean;
  sawStreamThinking: boolean;
  abortController: AbortController;
}
```

约束：

- 所有 turn 可变状态只存在于 `RuntimeTurn`；删除 runtime 级 `turnMetadata`、`bufferedUsageChunk`、`streamTransformState`、`usageTransformState`、`_autoTurnBuffer`、`_autoTurnSaw*`。
- runtime 同时最多一个 `collecting/projecting` turn；可有多个 `queued` user turn。
- `result` 只结算当前 active turn；不能读取 `responseHandlers` 数组尾部猜归属。
- turn 结束或取消后对象不可复用；晚到消息按 generation/phase 丢弃并记诊断日志。

#### 2.2 dequeue 时签发 user turn lease

改造 `/src/providers/claude/runtime/ClaudeMessageChannel.ts`：

- `enqueue()` 接收 `{ message, turnId }`，pending queue 保留 turnId；文本合并时同时合并到最早 queued turn，并把后来 query 的等待者显式并入该 lease，不能遗留无结果 handler。
- 新增构造回调 `onDequeue(turnId)`；仅在消息真正交给 SDK consumer 的两个位置同步调用：`enqueue()` 直接 resolve 前、`next()` 从 queue shift 后。
- `onTurnComplete(turnId)` 必须核对当前 active turnId；不匹配 fail-fast，不放行下一条。
- SDK async iterator 对外仍只 yield `SDKUserMessage`，不改变 Agent SDK 契约。

改造 `/src/providers/claude/runtime/ClaudeChatRuntime.ts:queryViaPersistent()`：

1. 创建 `RuntimeTurn(kind='user', phase='queued')` 与专属 handler；handler 存在不代表 active。
2. enqueue `{message, turnId}`。
3. `MessageChannel.onDequeue(turnId)` 才把该 turn 置为 active/collecting，并初始化其 transform state。
4. query generator 只读取自己 turn 的 handler；合并到其他 lease 时，应由 MessageChannel 返回 canonical turnId，并让 generator 订阅 canonical handler，禁止两个 handler 争同一 result。

#### 2.3 auto turn lease

`routeMessage()` 收到消息时：

- 若存在 active collecting user lease，投给它。
- 若不存在 active lease，创建 `RuntimeTurn(kind='auto')` 并同步发出 `onAutoTurnStarted(turnDescriptor)`；随后该轮所有消息归该 lease。
- task-notification 仍先执行 `dispatchTaskNotification()` 并早退于 transform；但无 active lease 时，它同时创建 auto lease并发 start 信号，以便在模型续轮首个普通 chunk 前锁住 feature 层。
- SDK `result` 把 auto lease 从 collecting 切为 projecting，await feature 投影；投影完成或超时取消后 settled，才调用 `MessageChannel.onTurnComplete(turnId)`。

“用户在 auto 首 chunk 前发送”的裁决：

- task-notification 已到并创建 auto lease：用户输入进入 feature queue。
- 尚无任何 auto 起始信号且用户消息已 dequeue：user lease 取得所有权；后续消息属于该 user turn。
- 仅注册 handler、尚未 dequeue：不取得所有权；auto lease优先。

### 3. feature 层 TurnCoordinator 仲裁

在 `/src/features/chat/controllers/` 新建 `TurnCoordinator.ts`，作为每个 tab 唯一的 UI turn 排他锁；`InputController` 与 runtime auto lifecycle 均通过它进入，不直接各自改 `ChatState.isStreaming/currentContentEl`。

接口固定：

```typescript
beginUserTurn(turnId): TurnProjectionLease
beginAutoTurn(turnId, runtimeGeneration): TurnProjectionLease
isBusy(): boolean
assertCurrent(lease): boolean
cancel(reason): void
finish(lease): void
```

行为：

- `begin*` 原子设置 `ChatState.isStreaming=true`、记录 feature generation、conversationId、tab lifecycle generation；同一时刻仅一个 lease。
- `InputController.sendMessage()` 的 busy 判断改为 `turnCoordinator.isBusy()`；auto turn 从 start 到状态投影完成期间，用户输入只进入现有 `queuedMessage` UI 队列，不创建 user/assistant message、不注册 runtime handler、不改 `currentContentEl`。
- 用户轮原有 `isStreaming` 初始化/清理迁入 coordinator；InputController 只创建消息内容与消费 query。
- auto turn `finish()` 后设置 `isStreaming=false`，再触发 `processQueuedMessage()`；不得在 runtime callback 尚未完成时发送下一轮。
- tab badge、取消按钮与后台 tab 状态沿用 `isStreaming` 回调，因此 auto turn 也自然显示 working/review 状态。

涉及文件：

- `/src/features/chat/controllers/TurnCoordinator.ts`：新建。
- `/src/features/chat/tabs/Tab.ts`：组装 coordinator，注册 runtime auto start/complete 回调。
- `/src/features/chat/tabs/types.ts`：`TabControllers` 增加 coordinator。
- `/src/features/chat/controllers/InputController.ts`：发送入口、用户 turn finally、队列放行改走 coordinator。
- `/src/core/runtime/ChatRuntime.ts`、`/src/core/runtime/types.ts`：增加 auto lifecycle callback 契约，Codex/OpenCode 空实现适配。

### 4. generation 与 cancellation

#### 4.1 双层 generation

每个 auto projection lease 捕获：

- runtime turn `id + generation`；
- feature `streamGeneration`；
- `conversationId`；
- tab `lifecycleState/generation`。

`handleAutoTriggeredTurn()` 每个 `await` 后调用 `lease.assertCurrent()`。失效后立即停止后续 state/DOM/save，只清本 lease 创建的临时资源；禁止清另一个新 turn 的全局状态。

#### 4.2 取消入口

以下路径必须调用 `TurnCoordinator.cancel()`，同时 runtime 取消对应 `RuntimeTurn.abortController`：

- `ConversationController.createNew(force)`、`switchTo()`；
- `destroyTab()`；
- runtime `resetSession()`、`syncConversationState()` 引发 session switch；
- `cleanup()`；
- 不保留 turn 的 persistent query close/restart。

restart 分两类：

- **transport/config restart，尚在 collecting**：`closePersistentQuery(..., { preserveTurn: true })` 不删除 active `RuntimeTurn` 的 chunks/metadata/usage/dedup；新 consumer 继续绑定该 turn。现有 `applyDynamicUpdates()` 必须使用此模式。
- **session switch/cleanup 或 projection 已开始**：generation++、abort；旧 callback 即使随后 resolve，也不得写 ChatState/DOM/save。仅清被取消 turn。

删除无作用域的 `resetTurnMetadata()`；初始化/清理改成 `createRuntimeTurn()` / `settleRuntimeTurn(turn)`。

### 5. StreamController 与 DOM 解耦

这是 v2 的理想版核心：业务状态先更新，DOM 是可选投影，不能用 `currentContentEl` 是否存在决定是否处理 chunk。

#### 5.1 TurnProjectionContext

在 `/src/features/chat/controllers/StreamController.ts` 引入显式上下文：

```typescript
interface TurnProjectionContext {
  turnId: string;
  message: ChatMessage;
  renderTarget: HTMLElement | null;
  textBuffer: string;
  thinkingBuffer: string;
  pendingToolIds: Set<string>;
  generation: number;
}
```

`handleStreamChunk(chunk, context)` 替代隐式读取全局 `ChatState.current*` 作为数据真相。活跃用户轮与 auto turn 都创建同类 context。DOM 相关字段仍可暂存在 context，但不再决定消息/任务状态是否创建。

- text：始终追加 `message.content` 与 `textBuffer`；有 renderTarget 才调 Markdown render。
- thinking：始终追加 `thinkingBuffer`；finalize 时始终写 `contentBlocks`，有 DOM 才创建/完成 thinking block。
- notice/error：先转换为规范化文本块并写 message，再可选渲染；不能因 `appendText()` 无 DOM而消失。
- tool_use/result：始终更新 `message.toolCalls/contentBlocks` 与 manager；DOM renderer 可为空。
- usage：与 DOM 无关，始终更新 scoped conversation state。

#### 5.2 SubagentManager 拆 domain 与 projection

改造 `/src/features/chat/services/SubagentManager.ts`：

- `createSyncTask/createAsyncTask` 的 domain record 创建不再要求 `HTMLElement`。
- `handleTaskToolUse()` 在 `parentEl=null` 时也立即依据 `run_in_background` 创建 sync/async domain entry；只有 mode 尚未知才进 pending。
- `renderPendingTaskFromTaskResult()` 即使无 DOM，也必须推断 mode、创建 domain entry、再处理同一 tool_result；不允许 `targetEl` 缺失提前 return。
- `syncSubagents` 不再存 DOM-bound `SubagentState` 作为唯一记录；拆为 `syncSubagentRecords: Map<id, SubagentInfo>` 与可选 `syncDomStates`。`asyncDomStates`同理只是 projector cache。
- `updateAsyncDomState()` 改名/收窄为 `projectAsyncSubagentState()`；没有 projector 时静默跳过，但 domain transition 与 `onStateChange` 已完成。
- 提供 `attachProjection(taskId, parentEl)`，当 tab 后续可见或 reload 时从 domain record 一次性渲染当前状态。

`SubagentManager` 的通知销账、Task tool_result 转正、TaskOutput 轮询解析都只操作 domain map；DOM 更新是 transition 后的观察者。

#### 5.3 auto turn 投影流程

`InputController.handleAutoTriggeredTurn(turn)`：

1. 取得已由 auto start 创建的 `TurnProjectionLease`。
2. 创建 assistant `ChatMessage` 并立刻加入 state；若有 DOM，`renderer.addMessage()` 一次，取得 renderTarget；无 DOM 则 renderTarget=null。
3. `subagentManager.resetSpawnedCount()`，创建 `TurnProjectionContext`。
4. 顺序 await 全部 chunks；每个 await 后校验 lease。
5. await context finalize；校验 lease。
6. 纯 usage、纯隐藏 TaskOutput 且无可见 message 内容时，从 state 删除临时 message；有 DOM时删除对应 bubble。不得生成 placeholder。
7. await state projection 完成后 `TurnCoordinator.finish()`；随后进入有界 save 队列并放行 MessageChannel，顺序见 §7。

### 6. usage 与阶段 1 边界

#### 6.1 usage

沿用 `/src/providers/claude/stream/transformClaudeMessage.ts` 两阶段规则：assistant 主 agent usage 提供 input/cache token，result `modelUsage` 只修正 authoritative contextWindow；禁止改用聚合 result token。

改造：

- usage state 属于 `RuntimeTurn`，`message_start` 仅 clear 当前 turn 的 state。
- auto turn 开始前 reset 该 projection 的 subagent spawn 计数；计数也应最终迁入 `TurnProjectionContext`，不再是 manager 全局 `_spawnedThisStream`。
- `StreamController` 的 usage sink 接收 lease 捕获的 conversationId；只更新该 conversation 对应 tab state。多 tab 共享同一 conversation 时，由 `ConversationProjectionRegistry`（见 §6.2）广播同一版本快照，禁止各 tab 互相覆盖。

#### 6.2 conversation 版本化投影

在 chat feature 增加轻量 `ConversationProjectionRegistry`，键为 conversationId，维护单调 `revision` 与最新 `messages/usage` 快照。每次 turn finalize 原子提交 `{conversationId, turnId, revision+1}`：

- 同一 conversation 的多个 tab 订阅同一快照；后台 tab/前台 tab 不各自保存旧副本。
- save queue 只保存 registry 最新 revision；旧 save 完成不能覆盖新 revision。
- 切回 tab 从 registry/hydrated conversation 渲染一次；不得把已实时投影的 turn 再 append。

#### 6.3 task-notification

`dispatchTaskNotification()` 保持 transform 前早退，不挪动：XML queue-operation 与 structured `system/task_notification` 只调用 `handleTaskNotification()`。通知可创建 auto lease/start 信号，但自身永不进入 StreamController。随后 TaskOutput chunks 只做 UI/投影兜底；阶段 1 的 terminal transition 幂等规则保持。

### 7. callback 饥饿与完成协议

state projection 必须 await；持久化不得无限占住 SDK turn。

新增每 conversation 一个 `ConversationSaveQueue`：

- 单飞串行，按 revision 合并：队列中仅保留最新待保存快照。
- auto callback 在 state projection 后提交 save request，并最多 await 3000ms（常量、可注入测试时钟）。
- 3s 内完成：正常结束。
- 超时：记录 warning/Notice，释放 runtime turn；save Promise 可后台继续，但提交前后都校验 revision，旧结果不得覆盖新状态。
- reject：记录失败并让下一次 save 重试最新 revision；不回滚内存投影。
- callback 自身另有 5000ms 总 watchdog。超时则 abort feature lease、清本 turn 临时 DOM、释放 MessageChannel；不得永久饥饿下一轮。

完成顺序：

```text
SDK result
→ RuntimeTurn.phase=projecting
→ await feature state projection（受 generation + 5s watchdog）
→ 原子提交 ConversationProjectionRegistry revision
→ enqueue save，最多 await 3s
→ feature TurnCoordinator.finish；用户 queuedMessage 可转发
→ RuntimeTurn settled
→ MessageChannel.onTurnComplete(turnId)
```

若 projection 取消/超时：不提交 revision、不 save；清本 turn并继续最后两步。用户 UI 队列只在 feature lease finish 后处理；SDK MessageChannel queue 只在 runtime settle 后 dequeue，双层均不早放行。

## 风险与权衡

- **改造面扩大**：理想版不接受“auto 特判管线”；MessageChannel、runtime、feature 与 SubagentManager 都需统一 turn/domain 模型。迁移代价高，但消除了同类竞态的结构性来源。
- **MessageChannel 文本合并语义**：多个 UI query 若已各自创建 generator，合并 lease 会复杂。推荐同时把 feature 排他前移，正常路径不再向 runtime 产生多个未 dequeue query；MessageChannel 的 canonical lease 仅作防御。
- **restart 语义**：只有同 session transport/config restart 可 preserve collecting turn；session switch、cleanup、projection 中 restart 一律 cancel。实现时必须枚举调用点，禁止默认 preserve。
- **多 tab 共享 conversation**：引入 revision registry 后，消息/usage 由 conversation 级快照裁决，不再以最后保存者为准；这是必要行为变化。
- **watchdog 丢展示而不丢权威终态**：feature projection 超时可丢该轮 UI，但阶段 1 通知已独立销账；下一次 transcript hydration 可重建投影。
- **迁移/落地代价**：预计涉及 15 个左右源码文件及 6 组测试；应分提交实施，但目标结构不可缩水为旧 handler/buffer 上继续叠条件。

### 分步落地与回滚

1. **S1：turn lease 基座。** 先改 MessageChannel、RuntimeTurn、dequeue 绑定、turn-scoped transform state；保持旧 auto callback适配器。验证归属与 restart preservation。回滚只影响 provider runtime。
2. **S2：feature 仲裁与 lifecycle cancellation。** 引入 TurnCoordinator，把用户轮与 auto start 纳入同一 `isStreaming` 排他状态；接 switch/new/destroy/restart generation。未完成 S2 禁止接 StreamController 回喂。
3. **S3：domain/DOM 解耦。** 先重构 SubagentManager domain-first，再重构 StreamController `TurnProjectionContext`；用现有用户轮测试保证行为等价。
4. **S4：接 auto 全量回喂。** 删除 `renderAutoTriggeredTurn()`，auto callback 顺序消费 chunks、finalize、空消息清理；阶段 1通知早退保持。
5. **S5：usage、conversation revision、save queue。** 完成多 tab 广播、usage turn scope、有界保存与 watchdog。
6. **S6：全量回归与运行时 V5。** 文档更新、构建、部署、手测。

每步独立提交；回滚按逆序。S3/S4 必须成对上线，禁止 domain 新旧双写或新旧渲染双开。
